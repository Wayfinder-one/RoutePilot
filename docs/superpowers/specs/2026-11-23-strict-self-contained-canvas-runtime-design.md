# 严格自包含画布、多 JEV 目录与引用同步设计

日期：2026-11-23

## 背景与目标

当前 `configs/cases/case-*.json` 只保存图结构；模型目录硬编码在 `scripts/demo/apply_cases.py`，JEV 依赖目标实例数据库。现有图格式还允许缺少运行配置并回退 SQLite，导致单份案例 JSON 不能独立恢复运行。

本设计将画布定义为不可变运行快照：保存后的画布包含路由图及全部非密钥运行配置，运行、试算、启用和重启恢复都只读取该快照。SQLite 是模型、provider、JEV、时段的管理目录和控制台下拉框数据源，不是已保存画布的运行时配置来源。

目标：

1. 所有保存的画布 JSON 和五个案例 JSON 都严格自包含，不保留无运行配置的旧文档兼容路径。
2. 支持多条 JEV 服务配置；不同画布可以选择不同 JEV，并把所选服务的完整非密钥配置固化进快照。
3. 修改或删除模型、JEV 时先展示受影响画布；确认后同步更新这些画布，禁止静默全局覆盖。
4. 数据库与画布不一致只影响检查提示，不改变快照执行结果。
5. JSON、图 API 和快照内容均不包含真实密钥。

## 核心边界

### 画布快照

每份已保存画布必须包含：

- `kind`、`version`、`name`、`timezone`、`sticky`、`root`，以及可选 `canvas` 坐标；
- `backends.providers`：provider 名称、base URL、`key_env`、推理方言；
- `backends.models`：模型 ID、上游模型 ID、provider 引用、能力及推理 profile；
- `jev`：服务 `id`、base URL、模型、`key_env`、超时、提示词、State 模板，或 `null`；
- `jev_window`：所选 JEV 的 `input_tokens` 和 `context_tokens`；
- `time_periods`：画布需要的时段定义。

四个运行字段 `backends`、`jev`、`jev_window`、`time_periods` 必须成组出现。缺少任何一个都拒绝解析、导入或保存，不自动从数据库补齐。`jev: null` 仅适用于没有问题节点的画布。

`jev` 示例：

```json
{
  "id": "production-d1",
  "base_url": "http://127.0.0.1:30104",
  "model": "d1-2B",
  "key_env": "PRODUCTION_JEV_API_KEY",
  "timeout_seconds": 10.0,
  "instructions": "你是一个模型路由器。",
  "state_template": "【待判断的用户请求】\n{request}"
}
```

密钥不从画布读取。运行时仅按服务/模型和端点匹配复用密钥存储，或读取 JSON 指定的环境变量名；真实 Key、Authorization 头及派生的密钥状态字段不得进入 JSON。

### 数据库目录

SQLite 保存：

- provider 和模型目录；
- 多条 JEV 服务及各自窗口；
- 时段目录；
- 密钥、用户、审计和运行状态。

管理页面的目录读取只查 SQLite，不再因活动画布不同而切换为活动画布内嵌配置。无活动画布时的固定模型直连是管理目录测试，不属于画布执行；它与画布快照构建使用分离的代码路径。

### 明确生成和更新快照

只有以下操作会生成或修改画布运行快照：

1. 新建画布：从当前数据库目录生成初始快照。
2. 导入完整 JSON：以文件内快照为准。
3. 在画布中选择模型或 JEV：把目录中的对应非密钥配置加入或替换到当前草稿。
4. 用户显式刷新画布运行配置。
5. 管理员确认模型、provider 或 JEV 变更的影响清单后，由服务端同步受影响画布。

数据库目录保存本身不再无差别重写所有画布。活动画布只在自身被确认同步或保存发布后生成新运行快照。

## 多 JEV 目录

### 数据模型

以 `jev_services` 表替代单行 `jev_config`。每条服务包含：

- 稳定字符串 `id`；
- `base_url`、`model`、`timeout_seconds`；
- `instructions`、`state_template`；
- `input_tokens`、`context_tokens`；
- `key_env`；
- 仅存在于数据库的 `api_key`。

窗口属于 JEV 服务，因为不同服务可能有不同上下文限制。选择或同步 JEV 时必须同时更新画布的 `jev` 与 `jev_window`，不允许混用两个服务的配置。

数据库迁移只执行一次：创建多服务表，把既有单行配置迁移为 `default` 服务并保留其密钥，然后删除旧表。运行时代码只保留多服务路径。环境变量 `ROUTER_JEV_URL` / `ROUTER_JEV_MODEL` 仅在空目录首次启动时创建 `default` 服务；`ROUTER_JEV_API_KEY` 只用于这个种子服务。其他服务使用各自的 `key_env` 或端点匹配的已存密钥。

### 管理 API 与页面

JEV 管理改为目录式接口：

- `GET /admin/jev`、`POST /admin/jev`；
- `GET /admin/jev/{service_id}`、`PUT /admin/jev/{service_id}`、`DELETE /admin/jev/{service_id}`；
- `POST /admin/jev/{service_id}/test`。

删除单配置形态的 `PUT /admin/jev`、`POST /admin/jev/test` 和独立的 `/admin/jev/window` 读写入口，不维护两套 DTO 或响应兼容层。JEV 页面提供服务列表、新建、编辑、删除和逐条连接测试；高级配置和窗口归属于当前编辑的服务。

JEV 连接测试使用页面所选的数据库服务配置，不读取活动画布快照。画布自身的 JEV 由检查路由验证。

## 画布编辑

“图设置”增加 JEV 下拉框，选项来自数据库 JEV 目录，展示 `id`、模型和地址。应用选择时，在同一个草稿历史项中替换 `runtime.jev` 与 `runtime.jev_window`。选择“不使用 JEV”后将 `jev` 设为 `null`；存在问题节点时，本地和服务端启用校验都给出硬错误。

模型下拉框来自数据库模型目录。选择模型时，在同一个草稿历史项中：

- 更新 target 的模型引用；
- 将该模型及其 provider 的非密钥目录信息加入画布快照；
- 按所选模型重新计算可选推理档位。

如果快照已有同 ID 模型，普通 target 编辑不静默覆盖其快照信息；数据库差异由检查提示，显式刷新或确认目录变更时才替换。

新建画布不得产生待保存时再物化的 `runtime: null` 中间契约。前端导入、序列化、dirty/undo 基线和 Python 文档解析都只接受完整运行字段。

## 引用影响与确认同步

### 影响清单

模型、provider、JEV 的更新或删除先扫描全部画布。若存在受影响画布，第一次写入返回 HTTP 409，`detail.code` 为 `impact_confirmation_required`，并包含：

- 资源类型和 ID；
- 每个受影响画布的 `id`、`name`、`enabled`、`document_sha256`；
- 使用位置：target、运行时目录或 JEV；
- 删除时可选的替代资源目录。

此时数据库和所有画布均不变。控制台展示影响清单，用户确认后携带每个画布的基线哈希重试。哈希不匹配返回 `graph_conflict`，要求重新读取影响清单，防止把过期确认应用到新画布。

### 更新

- 模型更新：同步所有包含该模型目录项的画布，并同步其 provider 与推理声明；target 的模型 ID 不变。
- provider 更新：同步所有包含该 provider 的画布；相关模型引用不变。
- JEV 更新：同步所有 `runtime.jev.id` 匹配的画布，同时替换 JEV 和窗口。

### 删除与替换

- 删除模型：只存在于运行时目录的模型可直接移除；被 target 引用时必须提供替代模型。服务端替换 target 引用、去重模型槽位并补入替代模型及 provider。旧推理档位在替代模型支持时保留，否则使用替代模型默认档位；无默认档位则为 `null`。
- 删除 JEV：凡画布快照引用该服务，都必须提供替代 JEV；同步替换 JEV 与窗口，避免留下无决策服务的问题节点。
- 删除 provider：只要数据库模型或画布快照模型仍引用它就拒绝。先通过模型更新/删除解除引用，不提供隐式 provider 替换。

### 原子性与发布

确认后的数据库写入和全部候选画布更新使用同一控制面用例：

1. 在单写锁和数据库事务中重算影响清单并核对基线哈希。
2. 构造所有候选画布，验证运行配置、图引用和启用级约束。
3. 预检并暂存全部文件，非活动画布先写，活动画布最后写。
4. 任一候选或文件失败时回滚数据库及已替换文件，不发布内存快照。
5. 全部成功并复核指纹后提交；仅当活动画布被修改时发布新快照。
6. 审计记录包含资源变更和同步画布 ID。

现有 `GraphBatch` 的预检、暂存、活动图最后写入和回滚机制应复用，不另建一套多文件写入协议。

## 保存、启用与检查

保存和启用只将画布自身的问题作为硬错误，包括：

- 缺少运行字段或字段非法；
- target 引用快照中不存在的模型；
- 模型引用不存在的 provider、provider 重复、模型 ID 重复；
- 问题节点存在但 `jev` 为 `null`；
- 推理档位、窗口、时段或兜底引用非法。

`/admin/try` 增加 `runtime_mismatch` 提示，逐项报告画布中声明的 JEV、窗口、provider、模型与数据库目录的差异及缺失项。数据库中存在但画布未声明的额外资源不算冲突。提示不阻止检查，也不改变执行配置；检查严格使用画布快照。

引用已存画布做草稿检查时继承该画布的快照；携带完整草稿时也必须携带完整运行字段。无画布标识的新草稿检查不能回退数据库生成隐式快照。

## 案例与脚本

五个 `configs/cases/case-*.json` 改为可直接导入的完整 v3 文档：

- 添加 `kind` 和 `version`，文件内不保存外部状态 `id` / `enabled`；决策组 ID 由 `manifest.json` 和文件名关联；
- 使用共同的 `demo-jev`：地址 `http://127.0.0.1:30104`、模型 `d1-2B`、窗口 `2048 / 4096`，不包含 Key；
- 使用 `demo-tap`：地址 `http://127.0.0.1:9300/v1`；
- 每个文件嵌入自身 target 实际使用的模型及完整 profile：
  - `case-industry`：六个行业模型；
  - `case-multimodal`：`vl-qwen35-4b`、`text-general`；
  - `case-reasoning`：`reason-qwen`、`reason-openai`、`reason-deepseek`；
  - `case-logic`：`industry-energy`、`ha-general`；
  - `case-ha`：`ha-slow-a`、`ha-slow-b`、`ha-fail`、`ha-general`；
- 案例所需时段直接内嵌，不依赖数据库已有定义。

`apply_cases.py` 删除独立维护的 `MODEL_SPECS` 等配置事实源，改为读取案例 JSON，生成数据库下拉框目录并部署画布。遇到影响确认时默认打印清单并停止；只有显式传入确认选项才同步现有画布。文档中的部署和验证步骤同步更新。

默认、生产和控制台示例 JSON 也补齐 JEV `id` / `key_env` 及完整必填字段。

## 移除的兼容路径

不保留以下行为或双轨代码：

- 无运行字段的 v3 文档解析、导入和保存；
- `runtime: null` 写控制字段及保存时物化；
- 从活动图或 SQLite 为已有画布补齐运行配置；
- 图执行、检查、启用校验中的数据库回退；
- 管理目录随活动图切换的投影；
- 单 JEV 与多 JEV 两套 API、DTO 或运行时分支；
- 数据库配置保存后无确认地批量重写全部画布。

无活动画布时的管理目录读取和固定模型直连不属于旧画布兼容，必须使用独立、明确的代码路径。

## 测试与验收

### 单元和契约测试

- Python 与前端只接受完整运行字段，部分字段和旧文档均拒绝；
- JEV 服务 CRUD、窗口归属、密钥脱敏和环境变量解析；
- 五个案例及默认/生产/示例文档可解析，模型与 provider 引用完整；
- 空 SQLite 实例仅凭画布 JSON 完成启动、JEV 调用和模型调用；
- 数据库不一致返回精确 `runtime_mismatch`，结果仍来自画布；
- 模型、provider、JEV 的影响清单、基线哈希冲突和未确认零写入；
- 更新同步、模型替换、JEV 替换、推理档位回退、目录项去重；
- 任一候选画布非法或写入失败时数据库和文件全部回滚；
- 数据库额外资源不误报，真实密钥不出现在文件、API 或快照中。

### 控制台测试

- 新建、导入、撤销/重做、保存和导出始终保留完整运行快照；
- 画布可选择不同 JEV，JEV 与窗口同步替换；
- 模型下拉选择会补齐当前草稿所需模型及 provider；
- 修改和删除资源展示受影响画布，确认前无请求副作用，确认后同步成功；
- 检查面板展示 mismatch，但不把数据库额外模型误报为冲突；
- 多 JEV 管理页、影响确认框及错误状态完成中英文检查。

### 最终验收命令

实现计划应列出并实际运行项目完整 Python 测试、现有图契约/控制台脚本，以及针对本功能的端到端测试。不得仅以模块导入或静态编译代替真实 JEV、模型调用和影响同步验证。
