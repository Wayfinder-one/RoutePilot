# RoutePilot 决策图规范（`sr-routing-graph` v4）

本文定义 RoutePilot 决策组的可移植文档格式、节点与连线文法、生命周期与部门规则、校验语义、执行语义与规范化哈希。接口层面的读写方式见[后端接口说明](后端接口说明.md)。

## 1. 三个层次

决策图相关对象有三个不同的层次，字段集合不能混用：

| 层 | 位置 | 内容 |
|---|---|---|
| **文件文档** | `$ROUTER_GRAPH_DIR/graphs/{id}.json`、导入/导出、`configs/*.json`、`router/console/routing/example.json` | `kind`、`version`、`name`、`departments`、`enabled`、`default`、`timezone`、`sticky`、`root`、`canvas`（可选）+ 四个运行字段 |
| **管理 API tree 对象** | `GET /admin/trees` 的 `trees[]`、`GET /admin/trees/{id}` 的 `tree`、`POST/PUT /admin/trees` 的请求体、`PUT /admin/trees/{id}/departments` 的请求体 | `id`、`name`、`enabled`、`default`、`departments`、`timezone`、`sticky`、`root`、`canvas`（可选）、`tree_revision`、`updated_at`、`document_sha256` + 四个运行字段；更新类写请求另带 `base_document_sha256`（新建不需要） |
| **行为 canonical** | `tree_revision` 的输入（§9.1） | 只含 `departments`、`timezone`、`sticky`、`root` 的行为字段与四个运行字段 |

- `kind`/`version` 只属于文件文档；把文件文档原样提交给管理面写接口会被“未知字段”（422）拒绝。
- `id`/`tree_revision`/`updated_at`/`document_sha256` 只属于存储与管理面；文件里写入它们同样会被拒绝。
- `enabled`/`default` 是文件文档的**必填持久化字段**，但**不是**普通保存的可写字段：新建与复制一律落为 `enabled: false, default: false`；控制台导入只替换草稿内容、不改生命周期，作为新组保存时是关闭态，保存到已有组则继承该组已存的生命周期；启停与默认图只能通过 `POST /admin/trees/{id}/enable`、`POST /admin/trees/{id}/disable`、`POST /admin/trees/{id}/default` 写入；普通 `PUT /admin/trees/{id}` 与 `PUT /admin/trees/{id}/departments` 永远从已存文档继承生命周期，请求体里出现 `enabled`/`default` 会 422（未知字段）。
- `departments` 是普通保存可写的字段（与部门设置端点共用同一条校验/写入/发布路径），并参与 `tree_revision`。
- 不再存在 `ROUTER_GRAPH_DIR/current` 指针：生命周期只由每份文件自己的 `enabled`/`default` 表达，仓储只按文件内容扫描。
- `canvas` 可省略；省略时表示所有节点都没有坐标。图根 `root` 是文件文档与管理 API tree 对象共享的嵌套对象，见 §3。

## 2. 文件文档

### 2.1 顶层字段

| 键 | 必填 | 类型与约束 |
|---|---|---|
| `kind` | ✅ | 必须恰为 `"sr-routing-graph"` |
| `version` | ✅ | 必须恰为整数 `4`；`true`/`false`/`"4"` 都拒绝 |
| `name` | ✅ | 字符串，可为空串；纯展示 |
| `departments` | ✅ | 字符串数组，见 §2.2；`[]` 表示不参与部门路由 |
| `enabled` | ✅ | JSON 布尔；生命周期，见 §2.3 |
| `default` | ✅ | JSON 布尔；为 `true` 时必须同时 `enabled: true`，否则解析失败 |
| `timezone` | ✅ | 非空 IANA 时区字符串；结构校验用 `ZoneInfo` 验证 |
| `sticky` | ✅ | `{enabled: bool, ttl_seconds: int}`；TTL 在 `[1, 31536000]` |
| `root` | ✅ | 图根，见 §3 |
| `canvas` | 否 | `{node_id: {x, y}}`；坐标必须是有限数，键必须是已存在节点 |
| `backends` | ✅ | `{providers, models}`，见 §5.1 |
| `jev` | ✅ | 服务档案对象或 `null`，见 §5.2 |
| `jev_window` | ✅ | `{input_tokens, context_tokens}`，见 §5.2 |
| `time_periods` | ✅ | 时段数组，见 §5.3 |

`name`、`departments`、`enabled`、`default`、`timezone`、`sticky`、`root` 属于非运行必填字段；`backends`、`jev`、`jev_window`、`time_periods` 四个运行字段**必须同时出现**。只带其中一部分（包括一个都不带）都报 `runtime fields must appear together`，不存在按数据库目录补齐的运行路径。

### 2.2 `departments` 规范化

`departments` 是硬约束的字符串数组，规范化规则只有一份实现（服务端 `tree_from_dict`，控制台 `RTGraph.normalizeDepartments` 与之等价）：

| 规则 | 说明 |
|---|---|
| 类型 | 必须是 JSON 数组，每一项必须是字符串；否则 `departments must be a list of strings` |
| 去空白 | 每项先 `strip()` 两端空白；结果为空串拒绝 |
| 长度 | 按 Unicode **码点**计 1–64（emoji 等非 BMP 字符算 1 个码点，不是 UTF-16 码元） |
| 控制字符 | 不允许 C0 控制字符（U+0000–U+001F）与 DEL（U+007F） |
| 文档内唯一 | 规范化后重复即拒绝：`duplicate department: <值>`（`" 财务部 "` 与 `"财务部"` 视为重复） |
| 排序 | 服务端按码点升序排序后保存与回传；输入顺序不影响结果，`[]` 合法 |
| 跨图唯一 | **不在单文件解析阶段校验**：草稿之间允许重复，唯一性只在启用图之间成立，由路由集装配校验（§7.1） |

部门值的比较是**精确字符串匹配**（区分大小写，不做大小写折叠）。文件里出现 `null` 等价于 `[]`。管理面两个写入路径的缺省语义不同：普通保存 `PUT /admin/trees/{id}` 省略 `departments` 时继承已存值，显式 `null` 表示清空；专用端点 `PUT /admin/trees/{id}/departments` 省略或显式 `null` 都表示清空该图的部门列表。

### 2.3 生命周期字段

- 每份文件必须显式携带 `enabled`/`default`；仓储不维护也不推导任何启用指针。
- 单文件解析只拒绝一种自相矛盾：`default: true` 且 `enabled: false`（`default graph must be enabled`）。
- **有启用图时恰好一张默认图** 是路由集不变量，不是单文件格式规则，在装配边界校验（§7.1）；零启用图合法，表示空路由集。
- 生命周期只能通过专用端点写入（第一张启用图自动成为默认图；之后的启用不改变默认图；停用默认图而仍有其它启用图 → 409 `default_graph_required`；停用最后一张启用图 → 空路由集；设为默认图是一个原子批次）。业务规则见[后端接口说明 §5](后端接口说明.md#5-管理面决策组)。
- 直接编辑文件（standalone JSON）仍是受支持的部署方式：文件按内容原样解析，生命周期不会被归一。手装出「有启用图但没有默认图」或「部门在启用图间重复」时，发布被跳过：启动时若从未成功发布过则 `/readyz` 未就绪（503）；运行中重载失败则保留上一次成功的路由集并报 `stale: true`。

### 2.4 拒绝顺序

解析按固定顺序执行，同一个坏文档可能命中不同报错：

1. 字节不是 UTF-8 JSON → `graph document is not valid UTF-8 JSON`
2. 顶层不是对象 → `graph document must be an object`
3. `kind` 或 `version` 不符 → `only sr-routing-graph v4 is accepted`
4. 缺少 `name`/`departments`/`enabled`/`default`/`timezone`/`sticky`/`root` 等非运行必填键 → `missing graph document fields: …`
5. 四个运行字段不齐全 → `runtime fields must appear together`
6. 出现未知顶层键 → `unknown graph document fields: …`
7. 其余逐层错误 → `default` 与 `enabled` 矛盾、部门规范化失败、`timezone`/`sticky`/图结构等具体字段错误

未知字段在每一层都会被拒绝：图根、节点、边、条件、提供方、模型、JEV、时段都不接受多余键。唯一的兼容例外是 `target.strategy` 与 `target.capability`：读取时接受并忽略，保存与导出不再写回，也不进入行为哈希。

### 2.5 最小文档

```json
{
  "kind": "sr-routing-graph",
  "version": 4,
  "name": "minimal",
  "departments": [],
  "enabled": false,
  "default": false,
  "timezone": "Asia/Shanghai",
  "sticky": {"enabled": false, "ttl_seconds": 600},
  "backends": {
    "providers": [
      {"name": "local", "base_url": "http://127.0.0.1:8000/v1", "key_env": "", "reasoning_format": "openai"}
    ],
    "models": [
      {"id": "m1", "upstream": "m1", "provider": "local", "profile": {}}
    ]
  },
  "jev": null,
  "jev_window": {"input_tokens": 1024, "context_tokens": 4096},
  "time_periods": [],
  "root": {
    "id": "root",
    "type": "graph",
    "nodes": [
      {"id": "start", "type": "start", "title": "开始"},
      {"id": "t1", "type": "target", "models": [{"model": "m1", "reasoning": null}], "priority": 1}
    ],
    "edges": [
      {"id": "e1", "source": "start", "source_port": "out",
       "target": "t1", "target_port": "in_1", "condition": null}
    ],
    "error_fallback": "t1"
  }
}
```

`jev: null` 在结构上永远合法；只有含 question 的图在**启用校验**时才要求 JEV 非空（`decision_service_unavailable`）。

## 3. 图根与节点

图根：

| 键 | 必填 | 约束 |
|---|---|---|
| `id` | ✅ | 非空字符串；纯标识，不进入行为哈希 |
| `type` | ✅ | 必须为 `"graph"` |
| `nodes` | ✅ | 节点数组，默认 `[]` |
| `edges` | ✅ | 边数组，默认 `[]` |
| `error_fallback` | ✅（可为 `null`） | 必须是已存在 target 的 id；结构校验要求非空且指向 target |

节点通用字段：

- `id`：非空字符串，图内唯一。
- `type`：`start`、`question`、`logic`、`condition`、`target` 之一。
- `title`：可选，字符串或 `null`，纯展示。
- 坐标**不是**节点字段；只能放在顶层 `canvas`。节点里出现 `position` 会被当成未知字段拒绝。

### 3.1 节点类型

| 类型 | 必填字段 | 专属字段 | 输出端口 | 输入槽 | 槽位语义 |
|---|---|---|---|---|---|
| `start` | `id`、`type` | — | `out: bool`，恒 `true` | ❌ | — |
| `question` | `id`、`type`、`question_type`、`instructions` | `options`（choice）、`criteria`（score） | 见 §3.2 | `in_1..in_n` | OR |
| `logic` | `id`、`type`、`operator` | `operator ∈ {and, or}` | `out: bool` | `in_1..in_n` | AND/OR，至少 2 条入边 |
| `condition` | `id`、`type`、`source` | `source ∈ {text, periods}`、`contains_any`、`periods` | `out: bool` | ❌ | — |
| `target` | `id`、`type`、`priority` | `models` | 无 | `in_1..in_n` | OR |

补充规则：

- 全图必须恰好一个 `start`。
- `condition` 与 `start` 不能作为边的目标；指向它们的边报 `edge_port_missing`。
- `question` 的 `instructions` 解析时允许空串，结构校验要求非空白。
- `target.models` 解析时默认 `[]`，结构校验允许为空，但**启用校验**要求至少一个模型（`target_models_required`）。

### 3.2 question

`question_type` 决定可用的配置字段与输出端口：

| 类型 | 允许的配置 | 输出端口 |
|---|---|---|
| `choice` | `options: [{key, label, capability}]`，2–255 个 | `selected.<key>: bool`、`prob.<key>: number`、`p_top: number`、`margin: number` |
| `noul` | 无额外配置 | `yes: number`、`no: number` |
| `score` | `criteria: [number, …]`，2–10 个有限数值 | `value: number` |

跨类型字段是硬错误：

- 非 `choice` 且 `options` 非空 → `<type> question must not declare options`
- 非 `score` 且 `criteria` 非 null → `<type> question must not declare criteria`
- `choice` 的 `options: []` 能通过解析，但结构校验报“至少 2 个选项”。
- 选项的 `key`、`label`、`capability` 都必须是字符串；结构校验要求 key/label/capability 非空、key 与 label 各自唯一。

choice 答案的端口填充规则：

1. 决策服务返回的 `probabilities` 键集合必须**恰好等于**该节点的选项 key 集合，否则整波失败。
2. `prob.<key>` 写入概率。
3. 按 `(-概率, 选项定义顺序)` 排序，第一名 `selected.<key> = true`，其余为 `false`。
4. `p_top` 为最高概率，`margin` 为第一名与第二名之差。

### 3.3 logic

- `operator` 只接受 `and` 或 `or`；`not`、`xor` 等直接解析失败。
- 输入 `in_1..in_n` 按三值逻辑合并，至少需要 2 条入边，否则 `logic_slot_count`。
- 门一旦算出 `true` 或 `false` 就写入端口并锁定；`unknown` 不写入，下一轮继续尝试。
- 三值规则：
  - `and`：任一 `false` → `false`；否则含 `unknown` 或不足 2 个输入 → `unknown`；否则 `true`。
  - `or`：任一 `true` → `true`；否则含 `unknown` 或不足 2 个输入 → `unknown`；否则 `false`。

### 3.4 condition

| 字段 | 说明 |
|---|---|
| `source` | `text`：按请求文本关键词匹配；`periods`：按当前时段匹配 |
| `contains_any` | 字符串数组，默认 `[]`；`source=text` 时结构校验要求非空且每项非空白 |
| `periods` | 字符串数组，默认 `[]`；`source=periods` 时结构校验要求非空且每项非空白 |

- `text` 匹配使用**经过输入窗口截断后的文本**，不是原始请求。
- 匹配是大小写敏感的简单子串包含；任一关键词命中即 `true`。
- 时段名必须出现在本文档的 `time_periods` 中，否则启用校验报 `unknown_period`。
- 解析层不禁止同时声明另一个 source 的字段（例如 `source=text` 同时带 `periods`），该字段会进入行为哈希但运行时完全不读。不要依赖这种写法。

### 3.5 target

| 字段 | 说明 |
|---|---|
| `models` | `[{model: str, reasoning: str \| null}]`；启用校验要求 `model` 指向本文档 `backends.models` 中的 id |
| `priority` | **JSON 整数**、≥1、全图唯一 |

- `priority` 写 `1.0` 能通过解析，但结构校验会报 `target_priority_invalid / not_integer`；`true` 则在解析层失败。
- 候选按 `(-priority, target_id)` 排序；正常图要求优先级唯一，因此不会出现真实并列。
- 多模型 target 在可用模型中**等概率随机**选择一个，不做最少在途比较；`inflight` 只用于轨迹与观测。
- `reasoning` 取该 target 中第一个 `model` 等于选中模型的条目的值。

### 3.6 输入槽

| 规则 | 说明 |
|---|---|
| 命名 | `in_([1-9][0-9]*)`；不允许前导零（`in_01` 非法） |
| 上限 | `1 ≤ N ≤ 400` |
| 占用 | 一个 `(target, in_N)` 只允许一条边；多余边报 `slot_conflict`，保留 edge id 最小者 |
| 连续性 | 不要求连续；`in_1`、`in_3` 合法 |
| 类型 | 槽位**不声明类型**；边的条件由源端口类型决定 |
| 激活 | 任一槽位求值为 `true` 即激活；`false` 与 `unknown` 都不激活 |
| 扇出 | 一个输出端口可以接多条边，无限制 |
| 排序 | 入边按槽位号数值升序；`via_port` 取编号最小的 true 槽 |

## 4. 边与条件

### 4.1 边对象

```json
{
  "id": "e-q-safe",
  "source": "q",
  "source_port": "prob.easy",
  "target": "safe",
  "target_port": "in_1",
  "condition": {"op": "gt", "value": 0.65}
}
```

| 键 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 非空字符串，图内唯一；不进入行为哈希 |
| `source` | ✅ | 源节点 id |
| `source_port` | ✅ | 必须在该节点的输出端口注册表中 |
| `target` | ✅ | 目标节点 id |
| `target_port` | ✅ | `in_N`；目标必须是 question/logic/target |
| `condition` | 否（缺省等价 `null`） | 见 §4.2 |

### 4.2 条件

条件只由**源端口类型**决定合法性，与目标槽位无关。

| 源端口类型 | 合法条件 | 求值 |
|---|---|---|
| `boolean` | `null`（等价 `= true`）或 `{"op":"is","value":true\|false}` | 源值 `null` → `unknown`；等于期望值 → `true`，否则 `false` |
| `number` | 必须有 `{op, value}`；`op ∈ gt/gte/lt/lte/eq/neq` | 源值 `null` → `unknown`；否则数值比较 |

- 阈值必须是有限数，且绝对值不超过 `1e9`（含边界）。
- `eq`/`neq` 是浮点精确比较。
- `is` 的 `value` 必须是 JSON 布尔。
- 数值源端口接到任何槽位都必须带数值比较条件；布尔源端口不要求条件。
- 条件非法时求值为 `unknown`，永不激活。正常路径下这类边已被结构校验拦下。

| 内层缺陷 | 对外 Issue code |
|---|---|
| 数值端口无条件 | `numeric_edge_condition_missing` |
| 数值算子非法 / 阈值非有限 / 超 `1e9` | `numeric_edge_condition_invalid` |
| 布尔端口用数值算子 / `is` 的值非布尔 | `boolean_edge_condition_invalid` |

### 4.3 三值传播

除 `start.out = true` 外，所有输出端口初始为 `unknown`（`null`）。运行中：

- 未激活的问题端口一直保持 `unknown`，下游边不会激活。
- 条件非法或源值类型不符时，该边为 `invalid`，按 `unknown` 处理。
- `unknown` 不会激活 question 或 target，也不会让逻辑门提前得出确定结论。

## 5. 运行配置

四个运行字段是画布快照的一部分，独立于数据库目录；保存后即固定。生命周期字段（`enabled`/`default`）与 `departments` 不在这四个字段里：`departments` 参与行为哈希，生命周期只参与路由集指纹与 `snapshot_revision`（§7、§9.3）。

### 5.1 `backends`

```json
{
  "providers": [
    {"name": "local", "base_url": "http://127.0.0.1:8000/v1",
     "key_env": "LOCAL_API_KEY", "reasoning_format": "openai"}
  ],
  "models": [
    {"id": "fast", "upstream": "qwen2.5-7b-instruct", "provider": "local",
     "profile": {"capability": "轻量通用请求"}}
  ]
}
```

提供方（允许且仅允许这四个键；`key_env`、`reasoning_format` 可省略并用默认值）：

| 字段 | 约束 |
|---|---|
| `name` | ID 正则；同一文档内唯一 |
| `base_url` | 非空、≤500 字符、无控制字符；末尾 `/` 被去掉 |
| `key_env` | 默认 `""`；非空时须匹配 `^[A-Za-z_][A-Za-z0-9_]*$`；只存环境变量**名** |
| `reasoning_format` | 默认 `openai`；须属于 `openai`、`deepseek`、`qwen`、`qwen-chat-template`、`openrouter`、`zai`、`together`、`string-thinking`、`ant-ling` |

模型（允许这四个键；四个字段都必填）：

| 字段 | 约束 |
|---|---|
| `id` | ID 正则；同一文档内唯一 |
| `upstream` | 非空、≤200 字符 |
| `provider` | 必须指向本文档已声明的提供方 |
| `profile` | 必填 JSON 对象；不允许 `NaN`/`Infinity`；`reasoning` 声明须匹配提供方方言 |

`profile` 仍是自由 JSON 元数据对象，但有两个约束：

- `capability` 会去空白，最长 2000 字符；空串则从结果中删除。
- 任意层级都不得出现 `api_key`、`authorization`、`key_present`、`key_source`（大小写与 `-`/`_` 归一后比较），否则解析失败。

### 5.2 `jev` 与 `jev_window`

`jev` 允许键：`id`、`base_url`、`model`、`key_env`、`timeout_seconds`、`instructions`、`state_template`。

| 字段 | 约束 |
|---|---|
| `id` | 必填，服务 ID 正则 |
| `base_url` | http/https，不能带 query 或 fragment |
| `model` | 非空字符串 |
| `key_env` | 默认 `""`，合法环境变量名 |
| `timeout_seconds` | 默认 `10.0`，`[0.1, 120]` |
| `instructions` | 默认内置中文提示词，非空 |
| `state_template` | 默认内置模板，必须恰好包含一个 `{request}` |

`jev_window`：

| 字段 | 约束 |
|---|---|
| `input_tokens` | 整数，`[256, 131072]` |
| `context_tokens` | 整数，`[512, 131072]` |
| 关系 | `input_tokens <= context_tokens` |

- `jev` 与 `jev_window` 属于同一服务，必须成组替换。管理面更新 `jev.id` 时必须同时提供新窗口。
- `jev` 为 `null` 时问题节点无从执行：结构校验仍可保存，但启用校验报 `decision_service_unavailable`。
- 窗口只影响送给 JEV 的输入文本：按“中日韩 1 token/字、其他 4 字符/token”保守估算并首尾保留截断。

### 5.3 `time_periods`

条目必须恰好是 `{name, days, start, end}`：

| 字段 | 约束 |
|---|---|
| `name` | 非空；文档内唯一 |
| `days` | 非空、无重复的 `0..6` 整数数组（0 = 周一） |
| `start` / `end` | `HH:MM`，`00:00`–`23:59` |

匹配规则（以请求时区换算后的本地时间为准）：

- `start == end`：该星期几全天命中。
- `start < end`：`[start, end)`。
- `start > end`：跨午夜，`minute >= start or minute < end`。

## 6. 校验与问题码

### 6.1 校验阶段

| 阶段 | 触发时机 | 范围 |
|---|---|---|
| 严格解析 | 导入、保存、试算、读取图文件 | 未知/缺失字段、类型、部门规范化、`default => enabled`、运行配置结构 |
| 结构校验 | 保存/试算/导入/启用 | start 数量、id 唯一、端口、槽位、条件、环、可达性、优先级、兜底、限额 |
| 启用校验 | 启用、启用图保存、目录写、快照构建 | 在结构校验之上增加模型登记、推理档位、时段引用、JEV 是否存在 |
| 路由集装配 | 启动加载、发布、启用集合写入前的候选校验 | 有启用图时恰好一张默认图；部门只在启用图之间唯一（§7.1） |

- 解析失败统一产出 `graph_parse_error`。
- 结构/启用问题产出各自的 code，不再折叠为 `graph_parse_error`。
- 前三个阶段的问题在管理面以 422 Issue 数组返回（`/admin/try` 把启用问题与目录差异放在 `warnings` 中，不阻止试算）。
- 路由集装配问题在只读边界（启动加载、重载、发布）映射为 503 `graph_storage_error`，`message` 形如 `invalid route set: no_default_tree`；已有一份成功发布的路由集时它继续服务，`/readyz` 报 `stale: true`（从未成功则 `ready: false`）。管理写路径在写盘前先做同样校验，命中时以 422 Issue（`no_default_tree` / `department_conflict`）拒绝，磁盘与已发布快照都不变。

### 6.2 Issue 形状

```json
{
  "code": "start_count",
  "zh": "start 节点数量必须为 1（当前 0 个）",
  "en": "Exactly one start node is required (found 0)",
  "node_id": "",
  "edge_id": "",
  "port": "",
  "level": "hard",
  "params": {"count": 0}
}
```

- `level`：`hard`（结构/启用）或 `hint`（仅 `runtime_mismatch`）。
- `node_id`、`edge_id`、`port` 不适用时为空串。
- `params` 始终存在，携带插值数据。
- 排序键：`(level, code, node_id, edge_id, port, params)`。

| code | 触发条件 | 关键 params |

| 项 | 上限 |
|---|---:|
| 节点 | 200 |
| 边 | 400 |
| question 节点 | 32 |
| 问题链深度 | 8 波 |
| choice 选项 | 255 |

## 7. 路由集、默认图与部门选图

### 7.1 启用集合与不变量

- 仓储扫描 `$ROUTER_GRAPH_DIR/graphs/*.json`，`enabled: true` 的图组成**启用集合**；生命周期只来自文件内容（没有 `current` 指针，也不推导）。
- 路由集不变量只有两条：
  1. **有启用图时恰好一张默认图**（`default: true` 唯一）；零启用图合法，表示空路由集。
  2. **部门在所有启用图之间唯一**；禁用草稿之间允许重复。
- 默认图负责兜底：请求的部门没有精确命中任何启用图时使用默认图。
- 违反不变量时，服务端抛路由集不变量错误 `no_default_tree` / `department_conflict`：加载/发布边界转成 503 `graph_storage_error`，并尽可能保留上一次成功的路由集（`/readyz` `stale: true`）；管理写路径在写盘前转成 422 Issue。

### 7.2 快照集与 `snapshot_revision`

- 每次发布都会对**全部**启用图执行启用校验、编译静态拓扑并装配快照；任一启用图不可用即跳过整个发布：已有一份成功发布的路由集时它继续服务，`/readyz` 报 `stale: true` 并给出 `last_load_error`；从未成功发布过则 `ready: false`。
- 发布单元 `RoutingSnapshotSet`：`snapshots`（`tree_id → 单图快照`）、`default_tree_id`、`department_tree_ids`（部门 → `tree_id`）、`snapshot_revision`、`content`、`fingerprint`。
- `snapshot_revision` 由三部分 canonical JSON 的 SHA-256 得到：
  - 默认图 id（零启用图时为 `null`）；
  - **排序后**的部门 → 图映射；
  - 每张启用图的单图 `snapshot_revision`（按 `tree_id` 排序）。
- 因此：默认图切换、部门映射变化、任意启用图的行为或部门变化都会改变路由集 `snapshot_revision`；纯草稿编辑不会（草稿不在启用集合里）。
- 单图 `snapshot_revision` 是本图运行快照内容的 SHA-256，与 `tree_revision`（§9.1）不同：前者覆盖快照装配后的运行结构，后者覆盖文档行为。

### 7.3 `route_fingerprint` 与重载

- `route_fingerprint` = SHA-256(canonical JSON of 按 `id` 排序的 `[{id, default, sha256}]`)，`sha256` 是启用图文件的字节哈希。
- 启停、默认切换、任一启用图文件字节变化都会改变指纹；只改禁用草稿不改变指纹，因此不会触发重载。
- 写者之外的副本每 2 秒轮询：指纹不变时完全跳过；变化时重建**完整**启用集合，而不是只换默认图。

### 7.4 选图

| 入口 | 选图规则 | 选图证据 |
|---|---|---|
| 公开 `POST /v1/chat/completions` | 永远使用默认图；请求出现 `x-sr-department` 一律 400 `department_header_not_allowed` | `x-sr-tree-id`、`x-sr-graph-selection: default` |
| 管理端测试对话 `POST /admin/test/chat/completions` | `model=auto`：可信 `x-sr-department`（百分号编码）精确命中部门图，空/未知部门回退默认图；固定模型直连跳过选图 | Auto：`x-sr-tree-id` + `x-sr-graph-selection`（`department`/`default`）；固定模型直连：`x-sr-selection: direct`，没有图头 |
| 检查路由 `POST /admin/try` 实际路由集路径（不带 `tree_id`/`root`） | 请求体 `department` 精确命中部门图，空/未知部门回退默认图 | 响应 `tree_id` + `graph_selection: "department"`/`"default"` |
| 检查路由草稿路径（带 `tree_id` 或 `root`） | 不参与路由集选图 | `graph_selection: null`，`tree_id` 是草稿快照 id（已存画布为它的 id，否则 `draft`） |

选图失败的错误码（数据面与管理面同码不同信封）：

| 情形 | 数据面 `/v1` | 管理面 `/admin/try` 路由集路径 |
|---|---|---|
| 路由集从未成功装配 | 503 `no_valid_snapshot` | 503 `no_valid_snapshot` |
| 零启用图（空路由集） | 503 `no_active_tree` | 503 `no_active_tree` |
| 有启用图但缺默认图（不变量损坏） | 503 `no_default_tree` | 503 `no_default_tree` |

## 8. 执行语义

一次请求的决策流程：

0. 按 §7.4 选定本次请求使用的图快照（公开数据面固定为默认图）。以下所有步骤都在该图快照内执行。
1. 按决策组时区换算 `now`，得到活动时段。
2. 对请求文本执行一次输入窗口截断；后续 condition 与 JEV 都使用截断后的文本。
3. 所有输出端口初始化为 `unknown`，仅 `start.out = true`。
4. 第一阶段求值所有 `condition` 节点（text 用子串匹配，periods 用活动时段）。
5. 定点求值逻辑门；门一旦得出 true/false 就锁定，不再翻转。
6. 对全部边各求值一次，记录槽位结果。
7. 激活扫描：任一槽位为 true 的 question 入队，target 写入候选集。
8. 波循环：把队内问题合并成一次 JEV 调用；成功后写端口，再回到第 5 步。
9. 没有新问题时结束。

约束与终局：

- 同一 question 在一次请求中最多执行一次；后续新槽位变 true 也不会重问。
- 同一 target 只记录第一次激活（`via_node`/`via_port`/`wave`）。
- 内部波次守卫为 32；校验层的问题链上限更严（8），正常图不会触发守卫。
- 候选按 `(-priority, target_id)` 排序，第一名获胜。
- 没有候选时使用 `error_fallback`。
- 失败波次：**不写任何端口，并清空此前所有波次累积的全部候选**，然后使用 `error_fallback`。
- `error_fallback` 同时处理“决策调用失败/超时/答案非法”和“正常运行但没有激活目标”；轨迹用 `kind` 区分 `error_fallback` 与 `otherwise`，对外 `selection_reason` 都是 `error_fallback`。

### 8.1 答案类型

| 问题类型 | 期望答案 | 端口 |
|---|---|---|
| `choice` | 键集合与选项完全一致的概率映射 | `prob.*`、`selected.*`、`p_top`、`margin` |
| `noul` | `{yes, no}` | `yes`、`no` |
| `score` | `{value}` | `value` |

一波内的答案必须覆盖本轮全部问题、类型正确；任何一个不符都让整波失败，不写部分端口。

### 8.2 调度

图决策完成后才进入模型调度：

1. 目标模型必须存在于画布 `backends.models`；不存在的标记为 `unregistered`。
2. 去掉熔断器已打开的模型（运行键见 §8.3），得到可用集合。
3. 若启用粘性且请求带 `x-sr-session-id`，先查粘性：
   - 命中条件：未过期、`tree_revision` 相同、target 相同、模型仍在可用集合。
   - 命中：固定该模型，`selection_reason = sticky`，续期 TTL。
   - 未命中或失效：删除旧条目，走下一步。
4. 多模型目标在可用集合中**等概率随机**选一个；单模型目标即该模型。
5. 没有可用模型 → `no_available_backend`（503）。
6. 粘性模型恰好失效时，按剩余模型重新选择，不返回 503。

模型被删除或熔断打开导致的不可用只影响选择，不改变图决策。

### 8.3 熔断与 inflight 的运行键

熔断器（`CircuitBreaker` / `BreakerStore`）与 inflight 计数使用带作用域的内部运行键：

```text
tree_scope(tree_id) = tree:<tree_id>
runtime_model_key(scope, model) = <scope>:<model>（scope 非空）或 <model>（固定直连）
```

- Auto 图路由的 scope 是 `tree_scope(snapshot.tree_id)`，即 `tree:<tree_id>`；固定模型直连的 `scope` 为空，继续使用裸逻辑模型 ID。
- 该键只用于 `CircuitBreaker` / `BreakerStore` 和 inflight 计数，不改变图文档、`tree_revision`、响应 `x-sr-model` 或账本 `model`——这些公开词汇仍是逻辑模型 ID。
- scope 来自 `RoutingSnapshot.tree_id`，跨副本稳定；不使用进程 ID、对象 ID、随机数或 `tree_revision`，因此重启、副本切换或普通图保存都不会让熔断状态漂移或重置。
- 同一张图的作用域在副本间稳定，但熔断与 inflight 的跨副本可见性不同：熔断 quarantine 经 `BreakerStore`（SQLite `breaker` 表，由 `router/upstream/breaker_worker.py` 周期推送与导入，启动时先加载）在副本间同步，受同步窗口限制（最坏约两轮同步间隔，期间副本间可能短暂不一致）；inflight 计数仍是进程内状态，重启或副本切换后归零。另一张图即使使用相同逻辑模型 ID，以及固定模型直连，都不受本图故障影响：一图熔断不波及它们，它们成功也不会重置本图的失败计数。

## 9. 规范化与哈希

### 9.1 `tree_revision`

`tree_revision = SHA-256(canonical_json(tree_behavior_dict))`，是**单图**行为版本。输入为：

```json
{
  "departments": ["财务部"],
  "timezone": "…",
  "sticky": {"enabled": true, "ttl_seconds": 1800},
  "root": {
    "type": "graph",
    "error_fallback": "safe",
    "nodes": [],
    "edges": []
  },
  "backends": {"providers": [], "models": []},
  "jev": null,
  "jev_window": {"input_tokens": 1024, "context_tokens": 4096},
  "time_periods": []
}
```

进入哈希的节点字段：

| 类型 | 字段 |
|---|---|
| `start` | `id`、`type` |
| `question` | `id`、`type`、`question_type`、`instructions`；choice 加 `options[{key,label,capability}]`；score 加 `criteria` |
| `logic` | `id`、`type`、`operator` |
| `condition` | `id`、`type`、`source`；非空时加 `contains_any`、`periods` |
| `target` | `id`、`type`、`models[{model,reasoning}]`、`priority` |

边的行为字段：`source`、`source_port`、`target`、`target_port`、`condition`。**边 id 不参与**。

`departments` 参与单图 `tree_revision`（规范化排序后的值）；`enabled`/`default` **不参与**单图 revision，但参与路由集指纹与 `snapshot_revision`（§7）。

### 9.2 排序与顺序敏感

| 集合 | 规则 |
|---|---|
| 节点数组 | 按 `id` 码点升序，输入顺序无关 |
| 边数组 | 按 `(target, 槽位号数值, source, source_port)` 升序，输入顺序无关 |
| `departments` | 规范化并去重后按码点升序，输入顺序无关 |
| `department_tree_ids` | 按部门码点升序，输入顺序无关 |
| `options` | 保持文档顺序，**顺序敏感** |
| `criteria` | 保持文档顺序，**顺序敏感** |
| `contains_any`、`periods` | 保持文档顺序，**顺序敏感** |
| `target.models` | 保持文档顺序，**顺序敏感** |
| `backends.providers`、`backends.models` | 保持文档顺序，**顺序敏感** |
| `time_periods` | 保持文档顺序，**顺序敏感** |

### 9.3 显式排除

以下变化不改变单图 `tree_revision`：

- 决策组 `id`、`name`、`enabled`、`default`（生命周期不进单图 revision；`default` 参与路由集 `snapshot_revision`）；
- 图根 `id`；
- 所有节点 `title`；
- `canvas` / 坐标；
- 边 `id`；
- 已下线的 `target.strategy`、`target.capability`；
- `tree_revision`、`updated_at`、`document_sha256` 自身；
- 任何密钥字段。

因此粘性以 `tree_revision` 为键时，改标题、改启用状态或挪节点不会让会话失效；改部门、改选项顺序会让它失效。

### 9.4 `document_sha256`

`document_sha256` 是**文件原始字节**的 SHA-256，用于乐观并发基线：

- 序列化固定为 `json.dumps(..., ensure_ascii=False, indent=2, allow_nan=False) + "\n"`。
- `PUT /admin/trees/{id}` 与 `PUT /admin/trees/{id}/departments` 必须用 `base_document_sha256` 带上当前 `document_sha256`，否则 409 `graph_conflict`。
- 影响确认也以该哈希为基线。

它和 `tree_revision` 不同：前者对“文件是否变化”敏感，后者只对“运行行为是否变化”敏感。

### 9.5 数值归一

- 图内数值统一转 `float`：`criteria: [1, 10]` 与 `[1.0, 10.0]` 同哈希。
- 运行配置额外把整数值的 float 转 int：`timeout_seconds: 10` 与 `10.0` 同哈希，`profile` 里的 `2048` 与 `2048.0` 同哈希。
- `target.priority` 例外：只接受 JSON 整数，`1.0` 会在结构校验阶段被拒绝。

### 9.6 跨运行时 canonical

服务端是 `tree_revision` 与 `snapshot_revision` 的唯一计算点；控制台 `RTGraph.behaviorCanonical` 必须逐字节一致，它只用于草稿 dirty/undo 与变更分类，不会写回。

- 序列化：键排序（`sort_keys`）、`ensure_ascii=False`、分隔符 `,`/`:`、拒绝 `NaN`/`Infinity`；控制台的 `stableStringify` 同口径。
- 字符串排序：规范按 **Unicode 码点**比较；Python `sorted()`/`sort_keys=True` 天然按码点。JS 默认为 UTF-16 码元，因此控制台的部门规范化显式使用码点比较器（`compareCodePoints`）与码点长度（`Array.from`）。
- 节点/边 id 的数组排序在规范里同样按码点；控制台对 id 使用 JS 字符串比较。对 BMP 范围内的 id 两者一致，含非 BMP 字符的 id 属跨运行时边界（`tree_revision` 始终以服务端 canonical 为准），不要依赖控制台的 dirty 判定。
- 浮点数：Python 用 `repr` 文本化（整数值浮点输出 `1.0`，指数切换点是 `1e-4`/`1e16`）；控制台用显式 `pythonFloat` 还原同一文本。
- 跨运行时契约 fixture 在 `tests/fixtures/graph_contracts.json`，任何一侧漂移都会让 `tree_revision` 或 dirty 判定失配。

## 10. 兼容与边界

- 只接受 `kind="sr-routing-graph"` 且 `version=4`。v3/v2 文档直接拒绝（`only sr-routing-graph v4 is accepted`），**不自动迁移**；不再有 `ROUTER_GRAPH_DIR/current` 指针，也没有把 v3 文件当旧文档接管的路径。
- `departments`/`enabled`/`default` 是必填字段：v3 文件缺少它们，因此天然被拒绝；手工补齐时必须同时满足 `default => enabled`。
- `logic/operator="not"` 直接拒绝，不提供旧 NOT 图兼容；反向判断请改用布尔输出取反或数值补比较（`> 0.65` 的取反写成 `<= 0.65`）。
- `target.strategy` 与 `target.capability` 可读但被忽略；保存与导出会丢弃。
- `question` 的跨类型字段是硬错误；`condition` 的跨 source 字段目前是“可解析但不执行”，不要依赖。
- 解析阶段与结构校验阶段是两套错误：未知字段/类型错误是 `graph_parse_error`；start 数量、槽位冲突等是各自的 code。
- 节点或边超限会在结构校验一开始直接返回，不会同时报告其他问题。
- `/admin/try` 的 `warnings` 中可能出现 `level=hard` 的启用问题；这表示“试算允许、启用会被拒”，不是矛盾。
