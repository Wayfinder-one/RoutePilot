# 计算日志重设计 · 三版原型（2026-11-04）

针对当前 `logs.html / logs.js / trace.js` 的三个问题：空白过多、无效字段过多、折叠态看不出计算路径。
三版**风格与现有控制台完全一致**——共用 `skin.css`，其变量、顶栏、pagehead、按钮、分段控件、13px 白卡
均直接取自 `router/console/shared.css`，不引入新配色、新字体、新圆角。差异只在信息架构。

> **评审结论（2026-11-04 18:34）**：选定 **方案 B**，但「最近 20 条」要改成与 A 一致的折叠行列表。
> 已据此更新 `b-audit-rail.html`：删掉顶部 20 格索引带，改为一行一条、点击内联展开的折叠行；
> 展开内容仍是 B 的七段审计轨道。A / C 保留作为对照。

## 打开方式

```bash
open docs/design/calc-log-v2/a-pathline.html
open docs/design/calc-log-v2/b-audit-rail.html
open docs/design/calc-log-v2/c-trace-matrix.html
```

纯静态稿，不连后端。三页右上角 A / B / C 可互相切换；筛选、展开/收起、键盘（B 用 ←→、C 用 ↑↓/ESC）均可操作。
`data.js` 提供 20 条仿真记录（与生产「最近 20 条」口径一致），事件名对齐 `trace.js` 的 14 类事件。

## 三版共同改动

| 项 | 当前实现 | 三版统一做法 |
|---|---|---|
| 计算路径 | 展开后纵向堆叠 section | 抽象成固定 **7 段主干**：输入 → 条件 → 门 → JEV → 候选 → 调度 → 模型 |
| 路径来源 | 手工拼装的展示层 | `derivePath(record)` 从真实 `trace` 事件派生，命中/跳过/中止三态可直接落地 |
| 统计区 | 4 张独立统计卡 | 压成 pagehead 右侧一行 KPI，不占纵向空间 |
| 执行结果 / 技术信息 | 9 项 + 10 项四列事实网格 | 收进单行折叠的「原始字段」，展开后默认不可见 |
| 跳过 / 中止阶段 | 与其他 section 等高 | 压成 22px 淡灰细条或直接留空格，不产生空白 |
| 视觉 | — | `skin.css` 统一令牌：`--indigo` 主色、白卡、`--line` 发丝边框、系统字体栈 |

## 三版对比

| | **A · 路径条** | **B · 折叠轨道（选定）** | **C · 追踪矩阵** |
|---|---|---|---|

| 主要任务 | 巡检、快速定位异常 | 巡检 + 单条排障「为什么这么路由」 | 横向对比多条路径差异 |

| 与现有代码距离 | 最近 | 较近（沿用内联展开） | 需改页面结构 |

## 决策要点

- **若优先巡检与落地成本** → A：保留现有列表与「点行内联展开」，只把路径链加进折叠行，改动集中在 `rowHtml()` 与 `detailHtml()`。
- **选定方向** → B：20 条保持 A 式折叠行，点击内联展开七段审计轨道；行内链负责「哪条异常」，
  展开轨道负责「为什么」。结论横幅与页脚结果区已并入展开区首行，原始字段折成一行；轨道懒渲染、可多开。
- **若优先密度与横向比对** → C：20 条 × 7 格信息量最高，但列宽在窄屏需收敛（<1120px 只留 JEV / 候选 / 模型）。

三版都已处理：失败点所在阶段保留失败原因、其后阶段标「中止」；`wave 0` 归入初始计算而非 JEV 轮次；
`prefers-reduced-motion` 下关闭全部入场动效；焦点圈、语义标签与 375 / 768 / 1440px 响应式已验。

## 架构修正（23:41）：从固定栅格改为事件驱动

**评审指出的问题**：默认决策组没有配置时间段，但「数据准备」里仍然显示「白天 / Asia/Shanghai」；
「不能每次新增加一个功能，就改一次日志」。

**根因**：第一版把当前功能清单写进了展示层 —— `STAGES` 常量、`derivePath()` 里硬编码的 7 个阶段对象、
以及「时段 / 时区 / Token 窗口」这些字段名。A / C 的固定列栅格更要求每行都画满 7 格，
没配置的阶段只能填空位或编默认值。**这是设计错误，不是数据问题**，因此 A / C 不再作为候选。

### 修正后的原则

日志只认识「事件 → 阶段」这个抽象，不认识任何具体功能：

| | 旧模型 | 新模型（B） |
|---|---|---|
| 阶段集合 | 固定 7 段，逐行画满 | trace 中实际出现过的 `phase`，没配置的阶段**不产生节点、不预留空位** |
| 阶段内容 | 前端写死的字段名 | 事件自带 `label / cell / summary / facts / tone`，前端纯投影 |
| 阶段顺序 | 前端写死的 section 顺序 | trace 首次出现顺序（生产 trace 本就按执行顺序追加） |
| 新增功能 | 改一次日志 | **后端按契约推事件，前端零改动** |
| 路径链 | 固定 7 列对齐 | 动态 chip 串，数量按请求而变 |

### 后端契约（落地时唯一一次改造）

每个 trace 事件附带以下展示字段，前端只做分组与投影：

| 字段 | 含义 |
|---|---|
| `phase` | 阶段 id；同一 phase 的事件归为一行。注意生产 `routing_error.stage` 已表示「失败于哪一步」，语义不同，故契约键取名 `phase` |
| `label` | 阶段显示名，如「Token 窗口」 |
| `cell` | 折叠行 chip 里的短判定值，如 `18tok` |
| `summary` | 展开轨道里的一句摘要，如 `18 → 18 tok` |
| `facts` | `[[键, 值], ...]` 依据项，前端最多取 3 条 |
| `tone` | `'' / hit / warn / bad`，驱动配色与分叉线 |

记录级另给 `route_label`（路径结论）。`data.js` 的 `deriveStages()` 就是这个契约的参考实现。

### 反例样本已内置

`r-8842` 是「默认决策组」：trace 里只有 `window / schedule / scheduled` 三个自描述事件，
因此日志只显示 `Token 窗口 → 模型调度 → 执行结果` **3 段**，
依据分别是「输入 / 输出 / 截断」「策略 / 可用」「模型 / 上游状态 / 总耗时」——
**没有白天、没有时区、没有条件、没有 JEV**，也没有任何空格子。
完整决策组 `r-8841` 是 6 段，路由失败 `r-8837` 是 5 段并带「路由中止」阶段。

### 剩余耦合点（同类问题，落地时一并收掉）

原型已验证核心机制，但以下四处仍带业务语义，属于**迁移兼容层**，不是新功能要走的路径：

1. `routeLabel()` 仍按 `selection_reason / sticky_hit` 推断结论 → 应统一由记录自带 `route_label`（已支持，旧记录走兼容推断）。
2. 展开区首行的「上游 / 路由 / 总耗时 / 轮次」仍是前端列名单 → 应改为记录自带 `metrics` 数组。
3.「原始字段」网格仍是前端列名单 → 应改为记录自带 `fields` 数组，或遍历事件元数据。
4. `FILTERS.sticky / fallback / error` 仍读业务字段 → 应改为按事件类型 / 阶段 `tone` 筛选
   （`FILTERS.jev` 已改为按 `deriveStages()` 的阶段 id 判断）。

历史（未自描述）事件由 `EVT_LEGACY_STAGE` 一次性映射、并复用 `derivePath()` 的旧摘要；
这是迁移适配层，待后端为存量记录补齐契约字段后即可整体删除。
