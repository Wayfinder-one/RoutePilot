方案 A · 设计注记（点击展开）

解决什么：把计算路径从「展开后纵向堆叠的 section」提到折叠行内。每行一条 7 段链 输入 › 条件 › 门 › JEV › 候选 › 调度 › 模型，命中为 indigo 实块、跳过为斜纹虚块、中止为红块 —— 不点开就能横向比较 20 条请求谁走了兜底、谁在 JEV 轮失败。

删掉了什么：4 张统计卡改为标题右侧一行 KPI；执行结果的 9 项事实、技术信息的 10 项 id / 版本 / 会话哈希全部收进单行「原始字段」；沿用现有控制台的 13px 白卡与 8px 卡间距，行高保持 42px，但删掉卡片内部的区块堆叠。

展开后只剩：逐阶段证据表（阶段 / 判定 / 依据 / 耗时），只列真正发生过的阶段。阶段值由 derivePath(record) 从生产 trace 事件直接派生，不是手工写的示意文字。

取舍：路径链吃掉约 560px 宽度，窄屏（<1080px）降级为 7 个着色圆点、<680px 隐藏链，只留 时间 / 文本 / 模型。适合巡检与快速定位，不适合逐事件排障（那是方案 C 的职责）。
