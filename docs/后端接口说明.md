# RoutePilot 后端接口说明

本文描述 RoutePilot（`sr-routing-graph` v3）对外的 HTTP 接口：数据面 `/v1/*`、管理面 `/admin/*`、健康检查与鉴权约定。字段名、状态码与错误形状均以当前实现为准；决策图文档本身见[决策图规范](决策图规范.md)。

- 默认监听：`ROUTER_HOST=127.0.0.1`、`ROUTER_PORT=8400`，即 `http://127.0.0.1:8400`
- 控制台：`/console/`；`GET /` 307 跳转到 `/console/index.html`
- OpenAPI：FastAPI 自带的 `GET /openapi.json`、`GET /docs`（公开）

## 1. 路径与鉴权总览

| 路径 | 鉴权 | 说明 |
|---|---|---|
| `POST /v1/chat/completions` | 无 | 路由数据面；JSON 或 SSE |
| `GET /healthz` | 无 | 存活探针，恒 `{"ok": true}` |
| `GET /readyz` | 无 | 快照就绪；未就绪返回 503，响应体仍是完整状态对象 |
| `POST /admin/login` | 公开 | 用邮箱口令换 Bearer token |
| 其余 `/admin/*` | Bearer token | 管理面；读接口所有角色可用，写接口需 `admin` |

### 1.1 登录与会话

```http
POST /admin/login
Content-Type: application/json

{"email": "admin@test.com", "password": "change-me"}
```

```http
200 OK
{
  "token": "3Xk...q9A",
  "expires_at": "2026-12-01T10:58:18+08:00",
  "user": {"id": "6b1f...", "email": "admin@test.com", "role": "admin"}
}
```

- token 是不透明随机串（256 位），只在登录响应出现一次；服务端只保存其 SHA-256。
- 示例中的口令是占位符；请换成部署时通过 `ROUTER_ADMIN_PASSWORD` 设置的值（内置种子默认 `1qaz@WSX`，首次登录后应修改）。
- 后续请求带 `Authorization: Bearer <token>`；方案名大小写不敏感。
- 会话有效期 `ROUTER_SESSION_TTL_HOURS`，默认 168 小时。`POST /admin/logout` 吊销当前 token；修改口令、重置口令、删除用户会吊销该用户的全部会话。
- 账号不存在、口令错误、账号被禁用，统一返回 `401 {"detail": "invalid email or password"}`，不区分原因。
- `ROUTER_USER_AUTH=0` 时不安装鉴权中间件：所有 `/admin/*` 直接开放，身份按服务账号（`role=admin`、`id=null`）处理；此时 `POST /admin/login` 恒返回 401，`GET /admin/me` 返回服务身份。该模式只适合本机开发。

### 1.2 角色

| 操作 | admin | viewer |
|---|---|---|
| 任意 `GET`/`HEAD`（`/admin/users*` 除外） | ✅ | ✅ |
| `POST /admin/logout`、`POST /admin/me/password` | ✅ | ✅ |
| `GET/POST/PUT/DELETE /admin/users*` | ✅ | ❌ 403 |
| 其他写操作（决策组、模型、提供方、JEV、时段、试算、测试对话） | ✅ | ❌ 403 |

- 未携带或无效 token：`401 {"detail": "unauthorized: /admin requires login"}`，并带 `WWW-Authenticate: Bearer`。
- 角色不足：`403 {"detail": "forbidden: admin role required"}`。
- 中间件先于路由执行：viewer 的畸形请求体也返回 403，而不是 422。
- 每次请求都会重新读取用户角色，降级或禁用立即生效。

## 2. 通用约定

- 请求与响应均为 UTF-8 JSON；管理面写接口的请求体用 `application/json`。
- `POST /v1/chat/completions` 与 `POST /admin/test/chat/completions` 直接按原始字节 `json.loads`，不检查 `Content-Type`，也不经过 Pydantic 请求模型校验。
- 请求体上限 10 MiB，超限返回 `413 {"error": {"message": "request_too_large"}}`（数据面错误形状，见 §2.3）。
- 决策组、模型、提供方与 JEV 服务的 ID 统一匹配 `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`；时间戳为带时区的 ISO-8601 字符串。
- 管理面列表接口没有分页、游标、ETag，也没有 204 响应；排序由各仓储决定。
- 多数管理面 DTO 设置 `extra="forbid"`：未知字段返回 FastAPI 的 422；登录与用户 DTO 例外，未知字段被忽略。
- `enabled` 不是可写字段：决策组只能通过 `/enable`、`/disable` 启停。

### 2.1 SSE

`POST /v1/chat/completions` 或 `/admin/test/chat/completions` 的请求体带真值 `stream` 时：

- 上游状态 `< 400` 时返回 `200`、`text/event-stream; charset=utf-8`，上游 SSE 字节原样转发，不注入心跳、不补 `[DONE]`。
- 上游 `4xx` 按原状态码与响应体透传；上游 `>= 500` 转为 `502 upstream_error`。
- 流在传输中失败会断开连接并记录 `upstream_error`；客户端断开记录 `client_disconnected`。

### 2.2 响应头

路由成功后，数据面响应（含流式）带：

| 头 | 取值 |
|---|---|
| `x-sr-model` | 本次实际选中的模型 ID（快照内的 ID，不是上游模型名） |
| `x-sr-selection` | `target` / `sticky` / `error_fallback` / `direct` |
| `x-sr-reasoning` | 实际注入的推理档位（仅当非空且无警告） |
| `x-sr-reasoning-warning` | `unsupported`：请求了模型不支持的档位，未注入推理 |

### 2.3 错误信封

管理面与数据面使用不同形状，客户端必须分别处理：

| 形状 | 出现位置 | 示例 |
|---|---|---|
| `{"detail": "<字符串>"}` | 管理面路由级 400/401/404/409/422 | `{"detail":"unknown tree main"}` |
| `{"detail": [Issue, ...]}` | 管理面图/配置校验 422 | 见 §2.4 |
| `{"detail": {"code": "...", ...}}` | 管理面 409/503 结构化错误 | `graph_conflict`、`impact_confirmation_required` |
| `{"error": {"message": "<机器码>"}}` | 数据面 `/v1/*` 与 `/admin/test/chat/completions` | `{"error":{"message":"no_active_tree"}}` |
| `{"detail": [{"type","loc","msg",...}]}` | FastAPI 请求模型校验失败 | 与 Issue 数组靠 `type`/`loc` 与 `code` 区分 |

数据面的 `message` 是机器码（`no_active_tree` 等），不是可展示文案；完整列表见 §3.1 与 §11。

### 2.4 Issue 对象

图与配置校验失败时，`detail` 是 Issue 数组；每个元素恰好包含：

```json
{
  "code": "question_incomplete",
  "zh": "choice 选项至少需要 2 个（当前 1 个）：q",
  "en": "A choice question needs at least 2 options (found 1): q",
  "node_id": "q",
  "edge_id": "",
  "port": "",
  "level": "hard",
  "params": {"kind": "choice_min_options", "count": 1}
}
```

- 没有 `message` 字段；文案固定为 `zh`/`en` 双语。
- `level` 只有 `hard` 与 `hint`；`runtime_mismatch` 是唯一的 `hint`。
- `params` 始终存在，携带插值与定位数据；`runtime_mismatch` 的 `params` 同时给出 `canvas` 与 `database` 两侧值。
- 数组按 `(level, code, node_id, edge_id, port, params)` 稳定排序，同一张图无论输入顺序如何都得到相同集合。
- 完整 code 表见[决策图规范 §6](决策图规范.md#6-校验与问题码)。

## 3. 数据面

### 3.1 `POST /v1/chat/completions`

请求体是 OpenAI 兼容 JSON。路由只读取以下字段，其余原样转发给上游：

| 字段 | 说明 |
|---|---|
| `messages` | 必须是数组；取最后一条 `role=="user"` 的文本作为路由输入。字符串内容直接使用；内容分片数组按 `text` 拼接 |
| `stream` | 真值时走 SSE；否则 JSON |
| `model` | **被忽略**：`/v1` 始终走决策图，转发前把 `model` 改写成所选后端的上游模型名 |

请求头：

| 头 | 说明 |
|---|---|
| `x-sr-session-id` | 可选，≤256 字符；用于会话粘性。超长返回 400 `invalid_session_id` |

成功响应是上游状态码与响应体的透传（非 JSON 响应体包装为 `{"raw": "<文本>"}`），额外加 §2.2 的响应头。

```http
POST /v1/chat/completions
x-sr-session-id: s-1
Content-Type: application/json

{"model": "ignored", "messages": [{"role": "user", "content": "帮我写一个快速排序"}]}
```

```http
200 OK
x-sr-model: fast
x-sr-selection: target

{"id":"chatcmpl-…","object":"chat.completion","model":"qwen2.5-7b-instruct",
 "choices":[{"index":0,"message":{"role":"assistant","content":"…"},"finish_reason":"stop"}],
 "usage":{"prompt_tokens":21,"completion_tokens":88,"total_tokens":109}}
```

失败：

| 状态 | `error.message` | 含义 |
|---|---|---|
| 400 | `invalid_json` | 请求体不是 JSON |
| 400 | `body_must_be_object` | 顶层不是对象 |
| 400 | `messages_must_be_list` | `messages` 不是数组 |
| 400 | `invalid_session_id` | `x-sr-session-id` 超过 256 字符 |
| 413 | `request_too_large` | 超过 10 MiB |
| 502 | `upstream_error` | 上游 5xx 或网络失败 |
| 503 | `no_valid_snapshot` | 进程内没有任何可用快照 |
| 503 | `no_active_tree` | 没有已启用的决策组 |
| 503 | `no_available_backend` | 选中目标的模型全部不可用 |
| 503 | `routing_invariant_violation` | 图执行超过波次守卫等内部不变量失败 |
| 503 | `routing_failed` | 其他路由内部错误 |

上游 4xx 按原状态码与响应体透传，不包装。

### 3.2 `GET /healthz`、`GET /readyz`

`/healthz` 恒 `200 {"ok": true}`。

`/readyz` 在快照就绪时返回 200，否则 503；两种情况响应体相同：

```json
{
  "ready": true,
  "stale": false,
  "active_id": "main",
  "document_sha256": "5f2a…",
  "loaded_at": "2026-11-24T10:58:19+08:00",
  "last_load_error": null
}
```

### 3.3 `POST /admin/test/chat/completions`

管理员专用测试对话，与 `/v1` 共用同一执行器，只多一处差异：

- 请求体 `model` 为 `"auto"`（或缺失）：走决策图。
- 请求体 `model` 为其他非空字符串：固定模型直连，跳过图、JEV 与粘性；模型经 SQLite 目录解析，不依赖活动快照。
- `model` 为空串或非字符串：`422 {"error":{"message":"invalid_model"}}`。
- 目录中不存在该模型：`404 {"error":{"message":"unknown_model"}}`。
- 其余请求/响应/流式行为与错误码同 `/v1`；固定直连时 `x-sr-selection: direct`。

## 4. 管理面：认证与用户

### 4.1 会话

| 方法与路径 | 权限 | 说明 |
|---|---|---|
| `POST /admin/login` | 公开 | 见 §1.1 |
| `POST /admin/logout` | 任意登录用户 | 吊销当前 token，返回 `{"ok": true}` |
| `GET /admin/me` | 任意登录用户 | `{id, email, role, expires_at}`；开放模式返回服务身份 |
| `POST /admin/me/password` | 任意登录用户 | `{old_password, new_password}`；`new_password` 至少 8 位；成功后吊销本人全部会话 |

修改口令错误：旧口令不符或服务账号 → 400；用户不存在 → 404。

### 4.2 用户管理

用户对象固定为 `{id, email, role, status, created_at, last_login_at}`，永不包含口令或哈希。

| 方法与路径 | 请求 | 成功 |
|---|---|---|
| `GET /admin/users` | — | `{"users":[...]}` |
| `POST /admin/users` | `{email, password, role?}`；`role` 默认 `viewer` | 201 `{"user":{...}}` |
| `PUT /admin/users/{id}` | 补丁 `{email?, role?, status?}`；缺省或 `null` 表示保留 | `{"user":{...}}` |
| `POST /admin/users/{id}/password` | `{new_password}` | `{"ok": true}`，吊销该用户全部会话 |
| `DELETE /admin/users/{id}` | — | `{"ok": true}`，同时删除会话 |

- 邮箱会做规范化与格式校验；重复邮箱返回 `409 {"detail":"email already exists"}`。
- 不能删除自己：`400 cannot delete yourself`。
- 不能删除、降级或禁用最后一个 active admin：`400`。
- 所有用户写操作追加 `changes` 审计行，detail 只含元数据。

## 5. 管理面：决策组

### 5.1 决策组对象

`GET /admin/trees/{id}` 返回的 `tree` 与列表元素同形。下面只展示字段形状，省略了可运行画布所需的完整节点与目录内容：

```json
{
  "id": "main",
  "name": "主决策组",
  "enabled": false,
  "timezone": "Asia/Shanghai",
  "sticky": {"enabled": true, "ttl_seconds": 1800},
  "root": {"id": "root", "type": "graph", "nodes": [], "edges": [], "error_fallback": "safe"},
  "canvas": {"start": {"x": 40, "y": 60}},
  "backends": {"providers": [], "models": []},
  "jev": null,
  "jev_window": {"input_tokens": 1024, "context_tokens": 4096},
  "time_periods": [],
  "tree_revision": "9c0d…",
  "updated_at": "2026-11-24T10:58:18+08:00",
  "document_sha256": "5f2a…"
}
```

- `canvas` 只在至少一个节点有坐标时出现；键必须是 `root.nodes` 里存在的节点 id。
- `tree_revision` 是行为哈希，`document_sha256` 是文件字节哈希；两者用途不同，见[决策图规范 §8](决策图规范.md#8-规范化与哈希)。
- `backends`、`jev`、`jev_window`、`time_periods` 是画布快照：读响应里总是四个齐全；新建时必须全部提供，更新时可以整体省略（继承旧快照）。服务端不会按数据库目录补齐。

### 5.2 端点

| 方法与路径 | 权限 | 说明 |
|---|---|---|
| `GET /admin/trees` | viewer | `{trees, snapshot_revision, graph_status}` |
| `POST /admin/trees` | admin | 新建，201 `{tree, snapshot_revision}` |
| `GET /admin/trees/{id}` | viewer | `{tree}` |
| `PUT /admin/trees/{id}` | admin | 补丁更新，返回 `{tree, snapshot_revision, graph_status, warnings}` |
| `POST /admin/trees/{id}/copy` | admin | 复制，201 `{tree, snapshot_revision}`；副本为关闭态 |
| `POST /admin/trees/{id}/enable` | admin | 启用，返回整个列表载荷 |
| `POST /admin/trees/{id}/disable` | admin | 停用，返回整个列表载荷 |

`graph_status` 即 `/readyz` 的状态对象。

#### 新建

`POST /admin/trees` 的请求体：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 否 | 缺省或 `null` 生成 12 位十六进制 id；须匹配 ID 正则 |
| `name` | 否 | `null` 视为空串 |
| `root` | 是 | 图根对象 |
| `canvas` | 否 | 节点坐标映射；`root` 内的节点不接受坐标，位置只从 `canvas` 读取 |
| `sticky` | 否 | `{enabled, ttl_seconds}`；`null` 用默认值 `{false, 1800}` |
| `timezone` | 否 | IANA 时区，默认 `Asia/Shanghai` |
| `backends` | **是** | 提供方与模型目录 |
| `jev` | **是** | 服务档案或 `null`（四个运行字段必须成组出现） |
| `jev_window` | **是** | `{input_tokens, context_tokens}` |
| `time_periods` | **是** | 时段数组 |

缺少任一运行字段都返回 422 `graph_parse_error`（“runtime fields must appear together”）。决策组新建后始终是关闭态；启用走 `/enable`。

#### 更新

`PUT /admin/trees/{id}` 是补丁语义：

- 缺省字段继承已存值；显式 `null` 按字段语义处理（`name` 清空、`timezone` 422、`sticky` 重置默认）。
- `id` 若出现必须与路径一致，否则 422 `tree id mismatch`。
- `base_document_sha256` **必填**，且必须等于当前 `document_sha256`；文档通过图校验后，缺失、格式错误或过期都返回 409 `graph_conflict`，并给出当前哈希：

```json
{"detail": {"code": "graph_conflict", "actual_document_sha256": "5f2a…"}}
```

- 若把 `jev.id` 改成另一个非空服务而同一请求没有带 `jev_window`，返回 422：窗口必须与服务一起替换。

#### 复制与启停

- 复制保留源画布快照；新 id 重复返回 409，源画布不存在返回 404。
- 启用前执行完整的启用级校验；校验失败返回 422 Issue 数组，不改变启用状态。
- 停用当前活动组会发布空快照；`/v1` 随后返回 `503 no_active_tree`。
- `enable`/`disable` 的响应是列表载荷，不是单个 tree。

## 6. 管理面：检查路由

`POST /admin/try` 对草稿或已存画布做 dry-run，不写数据库、不发布快照、不写粘性、不计 inflight。

请求体：

| 字段 | 说明 |
|---|---|
| `tree_id` | 可选；提供时先加载已存画布作为基线 |
| `root` | 可选；提供时覆盖基线图 |
| `canvas`、`timezone`、`sticky` | 可选覆盖 |
| `backends`、`jev`、`jev_window`、`time_periods` | 可选；要么随草稿完整提供，要么全部继承已存画布 |
| `text` | 路由输入，必须是字符串 |
| `session_id` | 可选，≤256 字符；dry-run 只读取粘性，不写入 |
| `now` | 可选 ISO-8601 时间，用于固定时段的判断 |

合并规则：

- 既没有 `tree_id` 也没有 `root` → 422。
- 有 `tree_id` 时，缺失字段继承已存值；提供了 `root` 时以草稿为准。
- 草稿只带部分运行字段时，不从数据库目录补齐；缺字段且无已存画布 → 422。

成功响应：

```json
{
  "outcome": {
    "type": "hit",
    "model": "fast",
    "target_id": "safe",
    "reasoning": null,
    "selection_reason": "target",
    "fallback_reason": null,
    "sticky_hit": false,
    "policy_path": "safe",
    "candidates": [
      {"target_id": "safe", "priority": 1, "via_node": "start", "via_port": "out", "wave": 0}
    ],
    "waves": [
      {"wave": 0, "questions": [], "duration_ms": 0.2, "failed": false, "error": null}
    ]
  },
  "answers": {},
  "trace": [],
  "tree_id": "main",
  "tree_revision": "9c0d…",
  "snapshot_revision": "ab12…",
  "warnings": [],
  "draft": false
}
```

- `outcome.type` 恒为 `"hit"`；路由未命中不是一种 outcome，而是 503。
- `draft` 为 `true` 表示本次带了 `root`。
- `answers` 按节点 id 给出决策答案：choice 为 `{probabilities, ranking, p_top, margin, usage, duration_ms}`，noul 为 `{yes, no, usage, duration_ms}`，score 为 `{value, usage, duration_ms}`。
- `warnings` 是 Issue 数组：启用级问题与画布/目录差异（`runtime_mismatch`，`level=hint`）。它们不阻止试算，也不改变执行配置。
- 结构校验失败 → 422 Issue 数组；路由未命中或无可用后端 → 503 字符串 detail。

## 7. 管理面：模型、提供方与目录

### 7.1 模型

模型对象：

```json
{
  "id": "fast",
  "upstream": "qwen2.5-7b-instruct",
  "provider": "local",
  "profile": {
    "capability": "轻量通用请求",
    "reasoning": {"efforts": {"off": null, "high": "high"}, "default": "off"}
  },
  "capability": "轻量通用请求",
  "reasoning": {
    "declared": true,
    "supported": true,
    "format": "openai",
    "efforts": [{"id": "off", "wire": null}, {"id": "high", "wire": "high"}],
    "default": "off",
    "supports_reasoning_effort": true
  }
}
```

| 方法与路径 | 权限 | 请求 / 行为 |
|---|---|---|
| `GET /admin/models` | viewer | `{"models":[...]}`；只读 SQLite 目录 |
| `POST /admin/models` | admin | `{id, upstream, provider, profile?}`；201 `{ok, model}` |
| `PUT /admin/models/{id}` | admin | 补丁 `{upstream?, provider?, profile?, impact_confirmation?}` |
| `DELETE /admin/models/{id}` | admin | 可选体 `{replacement_model_id?, impact_confirmation?}` |
| `GET /admin/model-catalog` | viewer | 内置提供方预设、推理方言与档位 |
| `POST /admin/fetch-models` | admin | 拉取上游 `/models` |

模型约束：

- `id` 符合 ID 正则；`upstream` 1–200 字符；`provider` 必须已存在。
- `profile` 可以是对象或 JSON 字符串；必须不含密钥字段、不含 `NaN/Infinity`；`capability` 最长 2000 字符。
- 删除仍被 target 引用的模型必须先提供 `replacement_model_id`，否则 422；替代模型未知 404，等于自身 422。
- 更新/删除被画布引用的模型走 §8 的影响确认协议。

`GET /admin/model-catalog` 返回：

```json
{
  "providers": [{
    "id": "openai", "name": "OpenAI", "base_url": "https://api.openai.com/v1",
    "key_env": "OPENAI_API_KEY", "reasoning_format": "openai",
    "key_env_present": true,
    "models": [{"id": "gpt-…", "name": "…", "context_window": 128000,
                "max_tokens": 16384, "tier": "large", "domains": [],
                "profile": {}, "reasoning": {}}]
  }],
  "formats": [{"id": "openai", "zh": "…", "en": "…", "needs_wire": true, "supports_sre": true}],
  "levels": ["off", "on", "minimal", "low", "medium", "high", "xhigh", "max"]
}
```

`POST /admin/fetch-models` 的 `{provider?}` 或 `{base_url?}` 至少提供一个（否则 422）。未知 provider 返回 404；上游不可达、非 JSON、缺少 `data` 数组返回 502。成功：

```json
{"endpoint": "http://127.0.0.1:8000/v1/models",
 "models": [{"id": "qwen2.5-7b-instruct", "name": "qwen2.5-7b-instruct"}]}
```

### 7.2 提供方

提供方对象：

```json
{
  "name": "local",
  "base_url": "http://127.0.0.1:8000/v1",
  "key_env": "LOCAL_API_KEY",
  "reasoning_format": "openai",
  "key_present": true,
  "key_source": "stored"
}
```

| 方法与路径 | 权限 | 说明 |
|---|---|---|
| `GET /admin/providers` | viewer | `{"providers":[...]}` |
| `PUT /admin/providers/{name}` | admin | 唯一的写入口，upsert |
| `DELETE /admin/providers/{name}` | admin | 被引用时不可删除 |

`PUT` 请求体：

| 字段 | 必填 | 说明 |
|---|---|---|
| `base_url` | 是 | 去空白、去末尾 `/`，1–500 字符 |
| `key_env` | 否 | 环境变量名，须匹配 `^[A-Za-z_][A-Za-z0-9_]*$` |
| `reasoning_format` | 否 | 默认 `openai`；非法值 422 |
| `api_key` | 否 | 省略 = 保留；`""` = 清除；非字符串 422 |
| `impact_confirmation` | 否 | 影响确认载荷，见 §8 |

- `api_key` 永不出现在响应里；响应只给 `key_present` 与 `key_source`（`stored`/`env`/`none`）。
- 若改了 `base_url` 却没有显式提供 `api_key`，旧密钥会被清除，避免被静默发往新地址。
- 删除提供方不可绕过引用检查：只要还有数据库模型或画布模型引用它，就返回 409 `provider_referenced`；确认不能绕过。

## 8. 影响确认（两阶段写）

模型、提供方、JEV 服务的更新/删除可能影响已保存画布。写操作分两阶段：

1. 未携带 `impact_confirmation` 且存在受影响画布：返回 409，数据库、画布文件、审计与快照全部不变。
2. 携带每幅受影响画布的当前 `document_sha256` 重试同一请求；服务端重新扫描并核对哈希后原子提交。

第一次 409 的载荷：

```json
{
  "detail": {
    "message": "该资源仍被画布引用，确认影响后才可写入",
    "code": "impact_confirmation_required",
    "resource": {"kind": "model", "id": "fast"},
    "affected_trees": [
      {
        "id": "main",
        "name": "主决策组",
        "enabled": true,
        "document_sha256": "5f2a…",
        "usage": {"targets": ["safe"], "runtime_catalog": true}
      }
    ],
    "replacements": []
  }
}
```

- `resource.kind` 为 `model`（带 `id`）、`provider`（带 `name`）或 `jev`（带 `id`）。
- `usage`：模型为 `{targets:[节点 id], runtime_catalog: bool}`；提供方为 `{runtime_catalog, models:{use:[模型 id]}}`；JEV 为 `{jev: "<服务 id>"}`。
- `replacements`：删除模型时列出其他模型 `{id, upstream, provider}`；删除 JEV 时列出其他服务 `{id, base_url, model, input_tokens, context_tokens}`；模型更新与提供方删除为 `[]`。

确认重试的请求体：

```json
{"impact_confirmation": {"trees": [
  {"id": "main", "document_sha256": "5f2a…"}
]}}
```

- 必须覆盖当前全部受影响画布，id 与哈希都一致；多一条、少一条或哈希过期都返回 409 `graph_conflict`，并给出当前哈希。
- `impact_confirmation` 结构不合法（不是带 `trees` 列表的对象）会被当作空确认，同样得到 409 `graph_conflict`。
- 无受影响画布时该字段无关，写操作直接成功。

确认后的提交在单写锁与单数据库事务内完成：重算影响、校验每份候选文档、暂存并替换文件、复核图指纹、写目录行与审计；任一失败整体回滚。仅当活动画布被同步时才发布新快照。

## 9. 管理面：JEV 服务目录

服务对象：

```json
{
  "id": "default",
  "base_url": "http://jev.test",
  "model": "NeoHorse-Jev-4B",
  "key_env": "ROUTER_JEV_API_KEY",
  "timeout_seconds": 5.0,
  "instructions": "你是一个模型路由器。……",
  "state_template": "【待判断的用户请求】\n{request}\n\n【任务】请选择最合适处理这条请求的模型。",
  "input_tokens": 1024,
  "context_tokens": 4096,
  "key_present": true,
  "key_source": "stored"
}
```

| 方法与路径 | 权限 | 说明 |
|---|---|---|
| `GET /admin/jev` | viewer | `{"services":[...]}` |
| `POST /admin/jev` | admin | 201 `{"service":{...}}`；新建不触发画布同步 |
| `GET /admin/jev/{id}` | viewer | `{"service":{...}}` |
| `PUT /admin/jev/{id}` | admin | 补丁更新；返回 `{service, synced_trees}` |
| `DELETE /admin/jev/{id}` | admin | 可选体 `{replacement_jev_id?, impact_confirmation?}` |
| `POST /admin/jev/{id}/test` | admin | 用数据库配置试连，`{text?}` |

字段约束：

- `id` 符合 ID 正则；`base_url` 为 http/https，不能带 query 或 fragment；`model` 非空。
- `key_env` 为空或合法环境变量名；`api_key` 永不回显。POST 时 `null` 表示不提供；PUT 时省略 = 保留（仅当地址与模型都不变）、`""` = 清除、`null` = 422。
- `timeout_seconds` 在 `[0.1, 120]`；`instructions` 非空；`state_template` 必须恰好包含一个 `{request}`。
- `input_tokens` 在 `[256, 131072]`，`context_tokens` 在 `[512, 131072]`，且 `input_tokens <= context_tokens`。
- PUT 的 body `id` 若出现，必须与路径一致。
- 删除仍被画布引用的服务必须提供 `replacement_jev_id`（不能是自身）；未知替代服务 404。

测试接口返回：

```json
{
  "selected_key": "a",
  "probabilities": {"a": 0.83, "b": 0.17},
  "p_top": 0.83,
  "margin": 0.66,
  "usage": {"prompt_tokens": 210, "completion_tokens": 8, "total_tokens": 218},
  "duration_ms": 96.4
}
```

`text` 缺省时用内置探针文本，最长 10000 字符；JEV 调用失败返回 502。

## 10. 管理面：时段、日志与概览

### 10.1 时段

| 方法与路径 | 权限 | 说明 |
|---|---|---|
| `GET /admin/time-periods` | viewer | `{periods:[...], now}` |
| `PUT /admin/time-periods` | admin | `{periods:[...]}` → `{ok, periods}` |

时段条目必须恰好是 `{name, days, start, end}`：

- `name` 非空且在同一目录内唯一。
- `days` 是非空、无重复的 `0..6` 整数数组（0 = 周一）。
- `start`/`end` 为 `HH:MM`；`start == end` 表示全天命中；`start > end` 表示跨午夜。

保存时若活动画布的启用级校验失败，返回 422 Issue 数组并回滚。

### 10.2 请求账本与审计

| 方法与路径 | 查询 | 返回 |
|---|---|---|
| `GET /admin/requests/recent` | `limit=20` | `{"requests":[...]}`，进程内环形缓冲，最多 20 条 |
| `GET /admin/requests/{request_id}/snapshot` | — | `{request_id, graph_snapshot_id, tree, trace, request}` |
| `GET /admin/requests/stats` | — | 写入队列与丢弃计数 |
| `GET /admin/changes` | `limit=50` | `{"changes":[{id, ts, kind, detail}]}` |
| `GET /admin/overview` | `days=14` | `{daily, routes, total, sticky, confidence, confidence_since}` |

说明：

- `requests/recent` 读取内存环，不是 SQLite；重启后回填的行没有 `text`、`trace`、`answers`、`node_labels`、`jev_probabilities`。
- 记录中包含 `route_label`、`metrics`、`fields` 等展示字段，以及 `snapshot_url`；`_graph_snapshot` 等内部字段不会返回。
- `requests/{id}/snapshot` 优先读内存环，再读不可变 SQLite 行；未知 id 返回 404，损坏快照返回 500。`tree` 为规范化后的画布文档。
- `/admin/overview` 的 `days` 只过滤 `daily`；`routes`、`total`、`sticky` 统计全部历史；`confidence` 只覆盖当前进程生命周期。
- `changes.kind` 为 `tree`/`model`/`provider`/`jev`/`time-periods`/`user`；detail 永不含密钥，只含 `api_key: set|cleared|unchanged` 或 `key_state` 之类的意图。

## 11. 错误码与状态码汇总

### 11.1 管理面

| 状态 | code / detail | 含义 |

## 12. 最小调用序列

```bash
BASE=http://127.0.0.1:8400

# 1. 登录，取 token
TOKEN=$(curl -s "$BASE/admin/login" -H 'content-type: application/json' \
  -d '{"email":"admin@test.com","password":"change-me"}' | jq -r .token)
AUTH="Authorization: Bearer $TOKEN"

# 2. 查看决策组与就绪状态
curl -s "$BASE/admin/trees" -H "$AUTH"
curl -s "$BASE/readyz"

# 3. 对已存画布做检查路由
curl -s "$BASE/admin/try" -H "$AUTH" -H 'content-type: application/json' \
  -d '{"tree_id":"main","text":"帮我写一个快速排序"}'

# 4. 启用并调用数据面
curl -s -X POST "$BASE/admin/trees/main/enable" -H "$AUTH"
curl -s "$BASE/v1/chat/completions" -H 'content-type: application/json' \
  -H 'x-sr-session-id: demo-1' \
  -d '{"messages":[{"role":"user","content":"帮我写一个快速排序"}]}'

# 5. 退出
curl -s -X POST "$BASE/admin/logout" -H "$AUTH"
```
