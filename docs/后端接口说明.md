# RoutePilot 后端接口说明

本文描述 RoutePilot（`sr-routing-graph` v4，多图启用集合）对外的 HTTP 接口：数据面 `/v1/*`、管理面 `/admin/*`、健康检查与鉴权约定。字段名、状态码与错误形状均以当前实现为准；决策图文档、部门规范化、生命周期与规范化哈希见[决策图规范](决策图规范.md)。

- 默认监听：`ROUTER_HOST=127.0.0.1`、`ROUTER_PORT=8400`，即 `http://127.0.0.1:8400`
- 控制台：`/console/`；`GET /` 307 跳转到 `/console/index.html`
- OpenAPI：FastAPI 自带的 `GET /openapi.json`、`GET /docs`（公开）

## 1. 路径与鉴权总览

| 路径 | 鉴权 | 说明 |
|---|---|---|
| `POST /v1/chat/completions` | 无 | 路由数据面；JSON 或 SSE |
| `GET /healthz` | 无 | 存活探针，恒 `{"ok": true}` |
| `GET /readyz` | 无 | 路由集就绪；未就绪返回 503，响应体仍是完整 `graph_status` 对象（§3.2） |
| `POST /admin/login` | 公开 | 用邮箱口令换 Bearer token |
| 其余 `/admin/*` | Bearer token | 管理面；读接口所有角色可用，写接口需 `admin` |

### 1.1 登录与会话

```http
POST /admin/login
Content-Type: application/json

{"email": "admin@test.com", "password": "change-me"}
```

```http
200 OK
{
  "token": "3Xk...q9A",
  "expires_at": "2026-12-01T10:58:18+08:00",
  "user": {"id": "6b1f...", "email": "admin@test.com", "role": "admin"}
}
```

- token 是不透明随机串（256 位），只在登录响应出现一次；服务端只保存其 SHA-256。
- 示例中的口令是占位符；请换成部署时通过 `ROUTER_ADMIN_PASSWORD` 设置的值（内置种子默认 `1qaz@WSX`，首次登录后应修改）。
- 后续请求带 `Authorization: Bearer <token>`；方案名大小写不敏感。
- 会话有效期 `ROUTER_SESSION_TTL_HOURS`，默认 168 小时。`POST /admin/logout` 吊销当前 token；修改口令、重置口令、删除用户会吊销该用户的全部会话。
- 账号不存在、口令错误、账号被禁用，统一返回 `401 {"detail": "invalid email or password"}`，不区分原因。
- `ROUTER_USER_AUTH=0` 时不安装鉴权中间件：所有 `/admin/*` 直接开放，身份按服务账号（`role=admin`、`id=null`）处理；此时 `POST /admin/login` 恒返回 401，`GET /admin/me` 返回服务身份。该模式只适合本机开发。

### 1.2 角色

| 操作 | admin | viewer |
|---|---|---|
| 任意 `GET`/`HEAD`（`/admin/users*` 除外） | ✅ | ✅ |
| `POST /admin/logout`、`POST /admin/me/password` | ✅ | ✅ |
| `GET/POST/PUT/DELETE /admin/users*` | ✅ | ❌ 403 |
| 其他写操作（决策组、模型、提供方、JEV、时段、试算、测试对话） | ✅ | ❌ 403 |

- 未携带或无效 token：`401 {"detail": "unauthorized: /admin requires login"}`，并带 `WWW-Authenticate: Bearer`。
- 角色不足：`403 {"detail": "forbidden: admin role required"}`。
- 中间件先于路由执行：viewer 的畸形请求体也返回 403，而不是 422。
- 每次请求都会重新读取用户角色，降级或禁用立即生效。

## 2. 通用约定

- 请求与响应均为 UTF-8 JSON；管理面写接口的请求体用 `application/json`。
- `POST /v1/chat/completions` 与 `POST /admin/test/chat/completions` 直接按原始字节 `json.loads`，不检查 `Content-Type`，也不经过 Pydantic 请求模型校验。
- 请求体上限 10 MiB，超限返回 `413 {"error": {"message": "request_too_large"}}`（数据面错误形状，见 §2.3）。
- 决策组、模型、提供方与 JEV 服务的 ID 统一匹配 `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`；时间戳为带时区的 ISO-8601 字符串。
- 管理面列表接口没有分页、游标、ETag，也没有 204 响应；排序由各仓储决定。
- 多数管理面 DTO 设置 `extra="forbid"`：未知字段返回 FastAPI 的 422；登录与用户 DTO 例外，未知字段被忽略。
- `enabled`/`default` 不是普通保存的可写字段：新建与复制一律落为关闭态；导入只替换草稿、不改生命周期（作为新组保存是关闭态，保存到已有组则继承其已存生命周期），启停与默认图只能通过 `POST /admin/trees/{id}/enable`、`/disable`、`/default`。普通 `PUT /admin/trees/{id}` 与 `PUT /admin/trees/{id}/departments` 的请求体里出现这两个字段会 422（DTO 未知字段）。
- `departments` 是普通保存可写字段（与部门设置端点共用同一路径）：字符串数组，规范化、文档内唯一、跨启用图唯一，详见[决策图规范 §2.2](决策图规范.md#22-departments-规范化)。

### 2.1 SSE

`POST /v1/chat/completions` 或 `/admin/test/chat/completions` 的请求体带真值 `stream` 时：

- 上游状态 `< 400` 时返回 `200`、`text/event-stream; charset=utf-8`，上游 SSE 字节原样转发，不注入心跳、不补 `[DONE]`。
- 上游 `4xx` 按原状态码与响应体透传；上游 `>= 500` 转为 `502 upstream_error`。
- 流在传输中失败会断开连接并记录 `upstream_error`；客户端断开记录 `client_disconnected`。

### 2.2 响应头

Auto 路由成功后，数据面响应（含流式）带：

| 头 | 取值 |
|---|---|
| `x-sr-model` | 本次实际选中的模型 ID（快照内的 ID，不是上游模型名） |
| `x-sr-selection` | `target` / `sticky` / `error_fallback` / `direct` |
| `x-sr-tree-id` | 本次实际使用的启用图 id；固定模型直连没有该头 |
| `x-sr-graph-selection` | 选图依据：`department` / `default`；固定模型直连没有该头 |
| `x-sr-reasoning` | 实际注入的推理档位（仅当非空且无警告） |
| `x-sr-reasoning-warning` | `unsupported`：请求了模型不支持的档位，未注入推理 |

`x-sr-tree-id`/`x-sr-graph-selection` 只描述“选了哪张图”，与“目标为什么胜出”的 `x-sr-selection` 互相独立。公开 `/v1` 永远使用默认图，因此它的 `x-sr-graph-selection` 恒为 `default`，绝不会是 `department`。

### 2.3 错误信封

管理面与数据面使用不同形状，客户端必须分别处理：

| 形状 | 出现位置 | 示例 |
|---|---|---|
| `{"detail": "<字符串>"}` | 管理面路由级 400/401/404/409/422 | `{"detail":"unknown tree main"}` |
| `{"detail": [Issue, ...]}` | 管理面图/配置/路由集校验 422 | 见 §2.4；含 `department_conflict`、`no_default_tree` |
| `{"detail": {"code": "...", ...}}` | 管理面 409/503 结构化错误 | `graph_conflict`、`impact_confirmation_required`、`default_graph_required` |
| `{"error": {"message": "<机器码>"}}` | 数据面 `/v1/*` 与 `/admin/test/chat/completions` | `{"error":{"message":"no_active_tree"}}` |
| `{"detail": [{"type","loc","msg",...}]}` | FastAPI 请求模型校验失败 | 与 Issue 数组靠 `type`/`loc` 与 `code` 区分 |

数据面的 `message` 是机器码（`no_active_tree`、`department_header_not_allowed` 等），不是可展示文案；完整列表见 §3.1 与 §11。

### 2.4 Issue 对象

图与配置校验失败时，`detail` 是 Issue 数组；每个元素恰好包含：

```json
{
  "code": "question_incomplete",
  "zh": "choice 选项至少需要 2 个（当前 1 个）：q",
  "en": "A choice question needs at least 2 options (found 1): q",
  "node_id": "q",
  "edge_id": "",
  "port": "",
  "level": "hard",
  "params": {"kind": "choice_min_options", "count": 1}
}
```

- 没有 `message` 字段；文案固定为 `zh`/`en` 双语。
- `level` 只有 `hard` 与 `hint`；`runtime_mismatch` 是唯一的 `hint`。
- `params` 始终存在，携带插值与定位数据；`runtime_mismatch` 的 `params` 同时给出 `canvas` 与 `database` 两侧值。
- 数组按 `(level, code, node_id, edge_id, port, params)` 稳定排序，同一张图无论输入顺序如何都得到相同集合。
- 完整 code 表见[决策图规范 §6](决策图规范.md#6-校验与问题码)。

## 3. 数据面

### 3.1 `POST /v1/chat/completions`

请求体是 OpenAI 兼容 JSON。路由只读取以下字段，其余原样转发给上游：

| 字段 | 说明 |
|---|---|
| `messages` | 必须是数组；取最后一条 `role=="user"` 的文本作为路由输入。字符串内容直接使用；内容分片数组按 `text` 拼接 |
| `stream` | 真值时走 SSE；否则 JSON |
| `model` | **被忽略**：`/v1` 始终走决策图，转发前把 `model` 改写成所选后端的上游模型名 |

公开数据面永远使用启用集合里的**默认图**，不按部门选图。请求头：

| 头 | 说明 |
|---|---|
| `x-sr-session-id` | 可选，≤256 字符；用于会话粘性。超长返回 400 `invalid_session_id` |
| `x-sr-department` | **禁止**：公开入口不接受部门选择。出现该头（即使值为空）即返回 400 `department_header_not_allowed`，与 `model` 无关 |

成功响应是上游状态码与响应体的透传（非 JSON 响应体包装为 `{"raw": "<文本>"}`），额外加 §2.2 的响应头。选图证据恒为默认图：

```http
POST /v1/chat/completions
x-sr-session-id: s-1
Content-Type: application/json

{"model": "ignored", "messages": [{"role": "user", "content": "帮我写一个快速排序"}]}
```

```http
200 OK
x-sr-model: fast
x-sr-selection: target
x-sr-tree-id: main
x-sr-graph-selection: default

{"id":"chatcmpl-…","object":"chat.completion","model":"qwen2.5-7b-instruct",
 "choices":[{"index":0,"message":{"role":"assistant","content":"…"},"finish_reason":"stop"}],
 "usage":{"prompt_tokens":21,"completion_tokens":88,"total_tokens":109}}
```

失败：

| 状态 | `error.message` | 含义 |
|---|---|---|
| 400 | `invalid_json` | 请求体不是 JSON |
| 400 | `body_must_be_object` | 顶层不是对象 |
| 400 | `messages_must_be_list` | `messages` 不是数组 |
| 400 | `invalid_session_id` | `x-sr-session-id` 超过 256 字符 |
| 400 | `department_header_not_allowed` | 公开数据面出现 `x-sr-department` 头 |
| 413 | `request_too_large` | 超过 10 MiB |
| 502 | `upstream_error` | 上游 5xx 或网络失败 |
| 503 | `no_valid_snapshot` | 进程内没有任何可用路由集 |
| 503 | `no_active_tree` | 空路由集：没有任何已启用的决策图 |
| 503 | `no_default_tree` | 有启用图但缺少默认图（路由集不变量损坏） |
| 503 | `no_available_backend` | 选中目标的模型全部不可用 |
| 503 | `routing_invariant_violation` | 图执行超过波次守卫等内部不变量失败 |
| 503 | `routing_failed` | 其他路由内部错误 |

上游 4xx 按原状态码与响应体透传，不包装。

### 3.2 `GET /healthz`、`GET /readyz`

`/healthz` 恒 `200 {"ok": true}`。

`/readyz` 返回发布器状态对象（也就是管理面各处的 `graph_status`）：路由集就绪时 200，否则 503；两种情况响应体相同：

```json
{
  "ready": true,
  "stale": false,
  "default_tree_id": "main",
  "enabled_tree_ids": ["finance", "main"],
  "snapshot_revision": "ab12…",
  "route_fingerprint": "9c0d…",
  "loaded_at": "2026-11-24T02:58:19+00:00",
  "last_load_error": ""
}
```

| 字段 | 含义 |
|---|---|
| `ready` | 进程内是否已有装配成功的路由集；零启用图的空路由集也是 ready |
| `stale` | 最近一次重载/发布是否失败；为 `true` 时保留此前的成功路由集继续服务（从未成功则 `ready: false`） |
| `default_tree_id` | 当前默认图 id；空路由集为 `null` |
| `enabled_tree_ids` | 当前启用图 id，按 id 升序 |
| `snapshot_revision` | 路由集的 `snapshot_revision`（§5.4）；**从未成功装配**时为 `""`，空路由集也有固定 revision（对 `{default_tree_id: null, department_tree_ids: {}, snapshots: {}}` 求哈希） |
| `route_fingerprint` | 已发布路由集对应的文件指纹；从未发布成功为 `""` |
| `loaded_at` | 最近一次成功发布的时间（UTC ISO-8601）；从未成功为 `""` |
| `last_load_error` | 最近一次加载/发布失败原因；正常为 `""` |

### 3.3 `POST /admin/test/chat/completions`

管理员专用测试对话，与 `/v1` 共用同一执行器，差异在模型与部门选择：

- 请求体 `model` 为 `"auto"`（或缺失）：走决策图，从已发布路由集选图。
- 请求体 `model` 为其他非空字符串：固定模型直连，跳过图、JEV 与粘性；模型经 SQLite 目录解析，不依赖路由集快照；`x-sr-selection: direct`，且**没有** `x-sr-tree-id` / `x-sr-graph-selection` 头。
- 可信部门头 `x-sr-department`：**仅 Auto 路径生效**。值按百分号编码解释（服务端严格解码）：ASCII 值可直接发送，含非 ASCII 时必须百分号编码；畸形 `%` 转义或非法 UTF-8 字节被拒绝。空值或解码后为空表示未声明部门；精确命中部门图 → 部门图，否则回退默认图。解码后超过 64 码点或含控制字符 → 400 `invalid_department`。部门绝不进入 OpenAI 请求体。
- Auto 路由的响应头包含 `x-sr-tree-id` 与 `x-sr-graph-selection`（`department`/`default`）；固定直连不产生图头，即使请求带了部门头也不参与选图（但仍会做 Header 解码校验）。
- `model` 为空串或非字符串：`422 {"error":{"message":"invalid_model"}}`。
- 目录中不存在该模型：`404 {"error":{"message":"unknown_model"}}`。
- 其余请求/响应/流式行为与错误码同 `/v1`（另有 400 `invalid_department`）。

## 4. 管理面：认证与用户

### 4.1 会话

| 方法与路径 | 权限 | 说明 |
|---|---|---|
| `POST /admin/login` | 公开 | 见 §1.1 |
| `POST /admin/logout` | 任意登录用户 | 吊销当前 token，返回 `{"ok": true}` |
| `GET /admin/me` | 任意登录用户 | `{id, email, role, expires_at}`；开放模式返回服务身份 |
| `POST /admin/me/password` | 任意登录用户 | `{old_password, new_password}`；`new_password` 至少 8 位；成功后吊销本人全部会话 |

修改口令错误：旧口令不符或服务账号 → 400；用户不存在 → 404。

### 4.2 用户管理

用户对象固定为 `{id, email, role, status, created_at, last_login_at}`，永不包含口令或哈希。

| 方法与路径 | 请求 | 成功 |
|---|---|---|
| `GET /admin/users` | — | `{"users":[...]}` |
| `POST /admin/users` | `{email, password, role?}`；`role` 默认 `viewer` | 201 `{"user":{...}}` |
| `PUT /admin/users/{id}` | 补丁 `{email?, role?, status?}`；缺省或 `null` 表示保留 | `{"user":{...}}` |
| `POST /admin/users/{id}/password` | `{new_password}` | `{"ok": true}`，吊销该用户全部会话 |
| `DELETE /admin/users/{id}` | — | `{"ok": true}`，同时删除会话 |

- 邮箱会做规范化与格式校验；重复邮箱返回 `409 {"detail":"email already exists"}`。
- 不能删除自己：`400 cannot delete yourself`。
- 不能删除、降级或禁用最后一个 active admin：`400`。
- 所有用户写操作追加 `changes` 审计行，detail 只含元数据。

## 5. 管理面：决策组

### 5.1 决策组对象

`GET /admin/trees/{id}` 返回的 `tree` 与 `GET /admin/trees` 的列表元素同形。下面只展示字段形状，省略了可运行画布所需的完整节点与目录内容：

```json
{
  "id": "main",
  "name": "主决策组",
  "enabled": true,
  "default": true,
  "departments": ["法务部", "财务部"],
  "timezone": "Asia/Shanghai",
  "sticky": {"enabled": true, "ttl_seconds": 1800},
  "root": {"id": "root", "type": "graph", "nodes": [], "edges": [], "error_fallback": "safe"},
  "canvas": {"start": {"x": 40, "y": 60}},
  "backends": {"providers": [], "models": []},
  "jev": null,
  "jev_window": {"input_tokens": 1024, "context_tokens": 4096},
  "time_periods": [],
  "tree_revision": "9c0d…",
  "updated_at": "2026-11-24T02:58:18+00:00",
  "document_sha256": "5f2a…"
}
```

- `canvas` 只在至少一个节点有坐标时出现；键必须是 `root.nodes` 里存在的节点 id。
- `tree_revision` 是行为哈希，`document_sha256` 是文件字节哈希；两者用途不同，见[决策图规范 §9](决策图规范.md#9-规范化与哈希)。
- `backends`、`jev`、`jev_window`、`time_periods` 是画布快照：读响应里总是四个齐全；新建时必须全部提供，更新时可以整体省略（继承旧快照）。服务端不会按数据库目录补齐。
- `departments` 是规范化后的部门列表：去空白、文档内去重、按码点升序；`enabled`/`default` 是服务端管理的生命周期，响应里如实反映已存文档。
- 新建与复制的决策组一律是 `enabled: false, default: false`；导入只替换草稿内容，作为新组保存时同样是关闭态，保存到已有组则继承其已存生命周期。生命周期只能通过 §5.3 的专用端点改变。

### 5.2 生命周期与多图规则

多张决策图可以同时启用，组成一条**启用集合**（路由集）；生命周期只存在于各自文件的 `enabled`/`default` 字段：

- 零启用图合法：表示空路由集。`/readyz` 仍是 `ready: true`，公开 `/v1` 返回 503 `no_active_tree`。
- 有启用图时**恰好一张默认图**。第一张被启用的图自动成为默认图；之后再启用别的图只增加启用成员，不改变默认图。
- 默认图兜底：请求部门没有精确命中任何启用图时，使用默认图。
- 停用默认图而仍有其它启用图 → `409`（结构化错误，见下）；必须先 `POST /admin/trees/{id}/default` 切换默认图。
- 停用最后一张启用图 → 发布空路由集（合法）。
- `enable`/`disable` 对已启用/已停用的图是幂等 200 无操作（不写盘、不发布）。
- 启用与默认图切换前都会执行启用级校验与候选路由集校验；失败返回 422 Issue 数组，磁盘与已发布快照都不变。
- 部门在**启用图之间**唯一；禁用草稿之间允许重复。若启用会让两个启用图声明同一部门 → 422 Issue `department_conflict`（`params.department` 与 `params.tree_ids`）。
- 普通保存（`PUT /admin/trees/{id}`）可以改 `departments`，但永远不能改生命周期；请求里出现 `enabled`/`default` 会 422（DTO 未知字段）。

默认图停用受限时返回：

```json
{"detail": {"code": "default_graph_required", "tree_id": "main"}}
```

### 5.3 端点

| 方法与路径 | 权限 | 说明 |
|---|---|---|
| `GET /admin/trees` | viewer | `{trees, snapshot_revision, graph_status}` |
| `POST /admin/trees` | admin | 新建，201 `{tree, snapshot_revision}`；强制关闭态 |
| `GET /admin/trees/{id}` | viewer | `{tree}` |
| `PUT /admin/trees/{id}` | admin | 补丁更新，返回 `{tree, snapshot_revision, graph_status, warnings}` |
| `PUT /admin/trees/{id}/departments` | admin | 部门设置，返回 `{tree, snapshot_revision, graph_status, warnings}` |
| `POST /admin/trees/{id}/copy` | admin | 复制，201 `{tree, snapshot_revision}`；副本为关闭态 |
| `POST /admin/trees/{id}/enable` | admin | 启用（第一张自动默认），返回整个列表载荷 |
| `POST /admin/trees/{id}/disable` | admin | 停用，返回整个列表载荷 |
| `POST /admin/trees/{id}/default` | admin | 设为默认图并启用，返回整个列表载荷 |

- “整个列表载荷”即 `{trees, snapshot_revision, graph_status}`，与 `GET /admin/trees` 同形；`enable`/`disable`/`default` 响应不是单个 tree。
- `snapshot_revision` 是本次发布的路由集 revision（§5.4）；`graph_status` 即 `/readyz` 的状态对象。
- 未知 tree id 的读/写一律 404。

#### 新建

`POST /admin/trees` 的请求体：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 否 | 缺省或 `null` 生成 12 位十六进制 id；须匹配 ID 正则 |
| `name` | 否 | `null` 视为空串 |
| `departments` | 否 | 字符串数组；缺省为空，规范化规则见[决策图规范 §2.2](决策图规范.md#22-departments-规范化) |
| `root` | 是 | 图根对象 |
| `canvas` | 否 | 节点坐标映射；`root` 内的节点不接受坐标，位置只从 `canvas` 读取 |
| `sticky` | 否 | `{enabled, ttl_seconds}`；`null` 用默认值 `{false, 1800}` |
| `timezone` | 否 | IANA 时区，默认 `Asia/Shanghai` |
| `backends` | **是** | 提供方与模型目录 |
| `jev` | **是** | 服务档案或 `null`（四个运行字段必须成组出现） |
| `jev_window` | **是** | `{input_tokens, context_tokens}` |
| `time_periods` | **是** | 时段数组 |

缺少任一运行字段都返回 422 `graph_parse_error`（“runtime fields must appear together”）。请求体不接受 `enabled`/`default`/`kind`/`version`（未知字段 422）；新建后始终是关闭、非默认态，启用走 `/enable`。

#### 更新

`PUT /admin/trees/{id}` 是补丁语义：

- 缺省字段继承已存值；显式 `null` 按字段语义处理（`name` 清空、`departments` 清空、`timezone` 422、`sticky` 重置默认）。
- `id` 若出现必须与路径一致，否则 422 `tree id mismatch`。
- `base_document_sha256` **必填**，且必须等于当前 `document_sha256`；文档通过图解析后，缺失、格式错误或过期都返回 409 `graph_conflict`，并给出当前哈希（若同一请求的图文档本身解析失败，先返回 422）：

```json
{"detail": {"code": "graph_conflict", "actual_document_sha256": "5f2a…"}}
```

- 生命周期不能通过保存写入：`enabled`/`default` 不是 DTO 字段（出现即 422），已存状态永远继承。
- 启用图的任何保存（含只改部门）都会重算并发布**整个启用集合**；禁用草稿的保存只写文件，不发布快照。
- 若把 `jev.id` 改成另一个非空服务而同一请求没有带 `jev_window`，返回 422：窗口必须与服务一起替换。
- 响应里的 `warnings` 目前恒为 `[]`，保留该字段是为了与检查路由的载荷一致。

#### 部门设置

`PUT /admin/trees/{id}/departments` 走与普通保存完全相同的校验/写入/发布/审计路径，只提交部门补丁：

```http
PUT /admin/trees/finance/departments
Content-Type: application/json

{"departments": ["财务部"], "base_document_sha256": "5f2a…"}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `departments` | 否 | 新部门数组；省略或 `null` 表示清空该图的部门列表 |
| `base_document_sha256` | **是** | 当前文档字节哈希；缺失/过期 → 409 `graph_conflict` |

成功返回 `{tree, snapshot_revision, graph_status, warnings}`。错误：

| 状态 | 形状 | 场景 |
|---|---|---|
| 409 | `{"detail": {"code": "graph_conflict", "actual_document_sha256": "…"}}` | 基线哈希缺失/过期 |
| 422 | Issue 数组 `graph_parse_error` | 部门类型/长度/控制字符/重复等规范化失败 |
| 422 | Issue 数组 `department_conflict` | 启用图之间部门冲突；`params.department`、`params.tree_ids` |
| 422 | Issue 数组 `no_default_tree` | 写盘后启用集合会缺少默认图（通常是手装文件已损坏） |
| 422 | FastAPI `extra_forbidden` | 请求体出现未知字段（如 `enabled`） |

该接口只改部门，不会改变生命周期；失败时磁盘与已发布快照都不变。

#### 复制、启停与默认图

- **复制** `POST /admin/trees/{id}/copy`：请求体 `{id?, name?}`（`id` 缺省自动生成）。保留源画布快照与部门，强制 `enabled: false, default: false`；新 id 重复返回 409，响应体是纯字符串 `{"detail": "tree <新 id> already exists"}`（没有 `code` 字段），源画布不存在返回 404。
- **启用** `POST /admin/trees/{id}/enable`：只启用目标图，不影响其它启用图；启用集合为空时该图同时成为默认图。启用前执行完整的启用级校验与候选路由集校验，失败返回 422 Issue 数组且不改变启用状态。
- **停用** `POST /admin/trees/{id}/disable`：停用目标图。目标图是默认图且仍有其它启用图 → 409 `default_graph_required`；停用最后一张启用图 → 发布空路由集，`/v1` 随后返回 503 `no_active_tree`。
- **设为默认图** `POST /admin/trees/{id}/default`：目标图设为默认并保持/进入启用，旧默认图保持启用但改为非默认，两者在同一原子批次内提交。目标图已是默认图时幂等 200 无操作。
- 以上三个生命周期端点都不修改部门；响应是完整列表载荷，调用方应据此刷新本地树列表与 `snapshot_revision`。

### 5.4 路由集状态 `graph_status`

`graph_status` 与 `/readyz` 的响应体是同一个对象：

```json
{
  "ready": true,
  "stale": false,
  "default_tree_id": "main",
  "enabled_tree_ids": ["finance", "main"],
  "snapshot_revision": "ab12…",
  "route_fingerprint": "9c0d…",
  "loaded_at": "2026-11-24T02:58:19+00:00",
  "last_load_error": ""
}
```

| 字段 | 含义 |
|---|---|
| `ready` | 是否已有装配成功的路由集（零启用图也是 ready） |
| `stale` | 最近一次加载/发布是否失败；为 `true` 时保留此前的成功路由集继续服务（从未成功则 `ready: false`） |
| `default_tree_id` | 默认图 id；空路由集为 `null` |
| `enabled_tree_ids` | 启用图 id 列表（升序） |
| `snapshot_revision` | 路由集 revision：默认图 id + 部门映射 + 各启用图快照 revision 的 canonical SHA-256 |
| `route_fingerprint` | 启用图 id/default/文档 sha256 的文件指纹；只改禁用草稿不改变它 |
| `loaded_at` | 最近一次成功发布时间；从未成功为 `""` |
| `last_load_error` | 最近一次失败原因（如 `invalid route set: no_default_tree`）；正常为 `""` |

## 6. 管理面：检查路由

`POST /admin/try` 有两种互斥的检查路径：

1. **实际路由集路径** —— 请求体既没有 `tree_id` 也没有 `root`。按已发布路由集选图（部门精确命中 → 部门图，空/未知部门 → 默认图），直接复用该启用图的已编译快照。
2. **草稿 envelope 路径** —— 请求体带 `tree_id` 和/或 `root`。合并草稿 envelope 后做 dry-run；`department` 在该路径被忽略。

两条路径都不写数据库、不发布快照、不写粘性、不计 inflight。

请求体：

| 字段 | 说明 |
|---|---|
| `tree_id` | 可选；提供时先加载已存画布作为基线，进入草稿路径 |
| `root` | 可选；提供时覆盖基线图，进入草稿路径 |
| `department` | 可选，**只在实际路由集路径生效**；字符串，两端去空白后 ≤64 码点、无控制字符，否则 422 `invalid department`；空串/缺省 = 未声明部门 |
| `canvas`、`timezone`、`sticky` | 可选覆盖（草稿路径） |
| `backends`、`jev`、`jev_window`、`time_periods` | 可选；要么随草稿完整提供，要么全部继承已存画布 |
| `text` | 路由输入，必须是字符串 |
| `session_id` | 可选，≤256 字符；dry-run 只读取粘性，不写入 |
| `now` | 可选 ISO-8601 时间，用于固定时段的判断 |

合并规则（草稿路径）：

- 有 `tree_id` 时，缺失字段继承已存值；提供了 `root` 时以草稿为准。
- 草稿只带部分运行字段时，不从数据库目录补齐；缺字段且无已存画布 → 422。
- 结构校验失败 → 422 Issue 数组。
- 启用级问题与画布/目录差异只作为 `warnings` 返回，不阻止试算。

成功响应：

```json
{
  "outcome": {
    "type": "hit",
    "model": "fast",
    "target_id": "safe",
    "reasoning": null,
    "selection_reason": "target",
    "fallback_reason": null,
    "sticky_hit": false,
    "policy_path": "safe",
    "candidates": [
      {"target_id": "safe", "priority": 1, "via_node": "start", "via_port": "out", "wave": 0}
    ],
    "waves": [
      {"wave": 0, "questions": [], "duration_ms": 0.2, "failed": false, "error": null}
    ]
  },
  "answers": {},
  "trace": [],
  "tree_id": "finance",
  "tree_revision": "9c0d…",
  "snapshot_revision": "ab12…",
  "warnings": [],
  "draft": false,
  "graph_selection": "department"
}
```

- `outcome.type` 恒为 `"hit"`；路由未命中不是一种 outcome，而是 503。
- 实际路由集路径：`tree_id` 是选中的启用图 id；`tree_revision`/`snapshot_revision` 是该图自己的单图 revision；`graph_selection` 为 `"department"` 或 `"default"`。
- 草稿路径：`draft` 为 `true` 表示本次带了 `root`；`tree_id` 是草稿快照 id（已存画布为其 id，否则 `"draft"`）；`graph_selection` 显式为 `null`；`warnings` 为 Issue 数组（启用级问题 + `runtime_mismatch` 提示）。
- 实际路由集路径的 `warnings` 恒为 `[]`：选中的是已经过启用校验并编译的固定快照。
- `answers` 按节点 id 给出决策答案：choice 为 `{probabilities, ranking, p_top, margin, usage, duration_ms}`，noul 为 `{yes, no, usage, duration_ms}`，score 为 `{value, usage, duration_ms}`。

失败：

| 状态 | 形状 | 场景 |
|---|---|---|
| 404 | `{"detail": "unknown tree <id>"}` | 草稿路径的 `tree_id` 不存在 |
| 422 | `{"detail": "try department must be a string"}` | `department` 不是字符串 |
| 422 | `{"detail": "invalid department"}` | 部门超长或含控制字符 |
| 422 | `{"detail": "try tree_id must be a nonempty string"}` | `tree_id` 显式传了空串/非字符串 |
| 422 | `{"detail": "try text must be a string"}` | `text` 不是字符串 |
| 422 | `{"detail": "invalid session_id"}` | `session_id` 超过 256 字符或不是字符串 |
| 422 | `{"detail": "now must be an ISO datetime"}` | `now` 不是合法 ISO-8601 |
| 422 | Issue 数组 | 草稿结构校验失败 |
| 503 | `{"detail": "no_valid_snapshot"}` | 路由集从未成功装配（实际路由集路径） |
| 503 | `{"detail": "no_active_tree"}` | 空路由集：没有任何启用图（实际路由集路径） |
| 503 | `{"detail": "no_default_tree"}` | 有启用图但缺少默认图（实际路由集路径，不变量损坏） |
| 503 | 字符串 detail | 路由未命中或无可用后端 |

| 字段 | 必填 | 说明 |
|---|---|---|
| `base_url` | 是 | 去空白、去末尾 `/`，1–500 字符 |

## 8. 影响确认（两阶段写）

模型、提供方、JEV 服务的更新/删除可能影响已保存画布。写操作分两阶段：

1. 未携带 `impact_confirmation` 且存在受影响画布：返回 409，数据库、画布文件、审计与快照全部不变。
2. 携带每幅受影响画布的当前 `document_sha256` 重试同一请求；服务端重新扫描并核对哈希后原子提交。

第一次 409 的载荷：

```json
{
  "detail": {
    "message": "该资源仍被画布引用，确认影响后才可写入",
    "code": "impact_confirmation_required",
    "resource": {"kind": "model", "id": "fast"},
    "affected_trees": [
      {
        "id": "main",
        "name": "主决策组",
        "enabled": true,
        "document_sha256": "5f2a…",
        "usage": {"targets": ["safe"], "runtime_catalog": true}
      }
    ],
    "replacements": []
  }
}
```

- `resource.kind` 为 `model`（带 `id`）、`provider`（带 `name`）或 `jev`（带 `id`）。
- `usage`：模型为 `{targets:[节点 id], runtime_catalog: bool}`；提供方为 `{runtime_catalog, models:{use:[模型 id]}}`；JEV 为 `{jev: "<服务 id>"}`。
- `replacements`：删除模型时列出其他模型 `{id, upstream, provider}`；删除 JEV 时列出其他服务 `{id, base_url, model, input_tokens, context_tokens}`；模型更新与提供方删除为 `[]`。

确认重试的请求体：

```json
{"impact_confirmation": {"trees": [
  {"id": "main", "document_sha256": "5f2a…"}
]}}
```

- 必须覆盖当前全部受影响画布，id 与哈希都一致；多一条、少一条或哈希过期都返回 409 `graph_conflict`，并给出当前哈希。
- `impact_confirmation` 结构不合法（不是带 `trees` 列表的对象）会被当作空确认，同样得到 409 `graph_conflict`。
- 无受影响画布时该字段无关，写操作直接成功。

确认后的提交在单写锁与单数据库事务内完成：重算影响、校验每份候选文档、按「非默认图先、默认图最后」暂存并替换文件、复核路由集指纹、写目录行与审计；任一失败整体回滚。发布门在写锁内、事务内判定：只要同步集合里含至少一张**启用图**（默认图或非默认启用图），COMMIT 之后就重算并发布**完整启用集合**；只同步禁用草稿时不发布。

```json
  "input_tokens": 1024,
  "context_tokens": 4096,
  "key_present": true,
  "key_source": "stored"
}
```

| 方法与路径 | 权限 | 说明 |
|---|---|---|
| `GET /admin/jev` | viewer | `{"services":[...]}` |
| `POST /admin/jev` | admin | 201 `{"service":{...}}`；新建不触发画布同步 |
| `GET /admin/jev/{id}` | viewer | `{"service":{...}}` |
| `PUT /admin/jev/{id}` | admin | 补丁更新；返回 `{service, synced_trees}` |
| `DELETE /admin/jev/{id}` | admin | 可选体 `{replacement_jev_id?, impact_confirmation?}` |
| `POST /admin/jev/{id}/test` | admin | 用数据库配置试连，`{text?}` |

字段约束：

- `id` 符合 ID 正则；`base_url` 为 http/https，不能带 query 或 fragment；`model` 非空。
- `key_env` 为空或合法环境变量名；`api_key` 永不回显。POST 时 `null` 表示不提供；PUT 时省略 = 保留（仅当地址与模型都不变）、`""` = 清除、`null` = 422。
- `timeout_seconds` 在 `[0.1, 120]`；`instructions` 非空；`state_template` 必须恰好包含一个 `{request}`。
- `input_tokens` 在 `[256, 131072]`，`context_tokens` 在 `[512, 131072]`，且 `input_tokens <= context_tokens`。
- PUT 的 body `id` 若出现，必须与路径一致。
- 删除仍被画布引用的服务必须提供 `replacement_jev_id`（不能是自身）；未知替代服务 404。

测试接口返回：

```json
{
  "selected_key": "a",
  "probabilities": {"a": 0.83, "b": 0.17},
  "p_top": 0.83,
  "margin": 0.66,
  "usage": {"prompt_tokens": 210, "completion_tokens": 8, "total_tokens": 218},
  "duration_ms": 96.4
}
```

`text` 缺省时用内置探针文本，最长 10000 字符；JEV 调用失败返回 502。

## 10. 管理面：时段、日志与概览

### 10.1 时段

| 方法与路径 | 权限 | 说明 |
|---|---|---|
| `GET /admin/time-periods` | viewer | `{periods:[...], now}` |
| `PUT /admin/time-periods` | admin | `{periods:[...]}` → `{ok, periods}` |

时段条目必须恰好是 `{name, days, start, end}`：

- `name` 非空且在同一目录内唯一。
- `days` 是非空、无重复的 `0..6` 整数数组（0 = 周一）。
- `start`/`end` 为 `HH:MM`；`start == end` 表示全天命中；`start > end` 表示跨午夜。

保存时会对**全部启用图**执行启用级校验（快照发布会重建完整启用集合）；任一启用图校验失败就返回 422 Issue 数组并回滚。

### 10.2 请求账本与审计

| 方法与路径 | 查询 | 返回 |
|---|---|---|
| `GET /admin/requests/recent` | `limit=20` | `{"requests":[...]}`，进程内环形缓冲，最多 20 条 |
| `GET /admin/requests/{request_id}/snapshot` | — | `{request_id, graph_snapshot_id, tree, trace, request}` |
| `GET /admin/requests/stats` | — | 写入队列与丢弃计数 |
| `GET /admin/changes` | `limit=50` | `{"changes":[{id, ts, kind, detail}]}` |
| `GET /admin/overview` | `days=14` | `{daily, routes, total, sticky, confidence, confidence_since}` |

说明：

- `requests/recent` 读取内存环，不是 SQLite；重启后回填的行没有 `text`、`trace`、`answers`、`node_labels`、`jev_probabilities`。
- 记录中包含 `route_label`、`metrics`、`fields` 等展示字段，以及 `snapshot_url`；`_graph_snapshot` 等内部字段不会返回。
- `requests/{id}/snapshot` 优先读内存环，再读不可变 SQLite 行；未知 id 返回 404，损坏快照返回 500。`tree` 为规范化后的画布文档。
- `/admin/overview` 的 `days` 只过滤 `daily`；`routes`、`total`、`sticky` 统计全部历史；`confidence` 只覆盖当前进程生命周期。
- `changes.kind` 为 `tree`/`model`/`provider`/`jev`/`time-periods`/`user`；detail 永不含密钥，只含 `api_key: set|cleared|unchanged` 或 `key_state` 之类的意图。

`requests/stats` 键：

```json
{
  "started_at": "2026-11-24T10:00:00+08:00",
  "ring_size": 12, "ring_limit": 20,
  "queue_size": 0, "queue_limit": 10000,
  "pending_snapshots": 0,
  "dropped_rows": 0, "dropped_updates": 0, "evicted_updates": 0,
  "partial_rows": 0,
  "ledger_write_failures": 0, "snapshot_write_failures": 0,
  "snapshot_pending_evictions": 0
}
```

## 11. 错误码与状态码汇总

### 11.1 管理面

| 状态 | code / detail | 含义 |
|---|---|---|
| 400 | 字符串 | 登录失败、旧口令错误、删除自己、最后一个 admin 保护等 |
| 401 | `unauthorized: /admin requires login` | 缺少或无效 token |
| 403 | `forbidden: admin role required` | viewer 执行写操作或访问用户管理 |
| 404 | 字符串 | 决策组、模型、提供方、JEV 服务或请求记录不存在 |
| 405 | — | 已删除的旧版 JEV 路由 |
| 409 | `graph_conflict` | 基线哈希缺失/过期，或影响确认过期 |
| 409 | `impact_confirmation_required` | 需要先确认受影响画布 |
| 409 | `default_graph_required` | 默认图之外仍有启用图时直接停用默认图；载荷 `{code, tree_id}` |
| 409 | `provider_referenced` | 提供方仍被数据库模型或画布模型引用 |
| 409 | 字符串 `tree <id> already exists` | 决策组 id 重复（`POST /admin/trees` 新建或 `/copy`）；`detail` 是纯字符串，没有 `code` 字段 |
| 422 | Issue 数组 | 图/配置/路由集校验失败；包含 `graph_parse_error`、`department_conflict`、`no_default_tree` 等 |
| 422 | 字符串 | DTO 类型、资源 ID、字段约束失败；请求体未知字段（`extra_forbidden`） |
| 503 | `graph_read_only` | 只读副本 |
| 503 | `graph_storage_error` | 共享图存储不可读/写入失败，或加载时路由集不变量损坏（`message` 如 `invalid route set: no_default_tree`） |
| 502 | 字符串 | JEV 测试失败、上游模型发现失败 |

### 11.2 数据面

见 §3.1。补充：

- `/admin/test/chat/completions` 额外有 `404 unknown_model`、`422 invalid_model` 与 `400 invalid_department`（可信部门头解码失败）。
- 公开 `/v1/chat/completions` 额外有 `400 department_header_not_allowed`（不接受 `x-sr-department`）。
- 选择失败错误：`no_valid_snapshot`（路由集从未装配）、`no_active_tree`（空路由集）、`no_default_tree`（启用集合缺默认图）。

## 12. 最小调用序列

```bash
BASE=http://127.0.0.1:8400

# 1. 登录，取 token
TOKEN=$(curl -s "$BASE/admin/login" -H 'content-type: application/json' \
  -d '{"email":"admin@test.com","password":"change-me"}' | jq -r .token)
AUTH="Authorization: Bearer $TOKEN"

# 2. 查看决策组与路由集状态
curl -s "$BASE/admin/trees" -H "$AUTH"
curl -s "$BASE/readyz"

# 3. 对已存画布做检查路由（草稿路径）
curl -s "$BASE/admin/try" -H "$AUTH" -H 'content-type: application/json' \
  -d '{"tree_id":"main","text":"帮我写一个快速排序"}'

# 4. 启用决策组（第一张自动成为默认图），并按部门检查实际路由集
curl -s -X POST "$BASE/admin/trees/main/enable" -H "$AUTH"
curl -s "$BASE/admin/try" -H "$AUTH" -H 'content-type: application/json' \
  -d '{"department":"财务部","text":"帮我写一个快速排序"}'

# 5. 调用数据面（公开入口永远使用默认图，不带部门头）
curl -s "$BASE/v1/chat/completions" -H 'content-type: application/json' \
  -H 'x-sr-session-id: demo-1' \
  -d '{"messages":[{"role":"user","content":"帮我写一个快速排序"}]}'

# 6. 退出
curl -s -X POST "$BASE/admin/logout" -H "$AUTH"
```
